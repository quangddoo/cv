# Spring Boot Actuator: Giám sát Production & Quản lý bảo mật thực chiến

## ⚡ Tóm tắt ngắn (30s)
**Spring Boot Actuator** là thư viện hạ tầng cung cấp các tính năng "sẵn sàng cho production" (production-ready features) giúp giám sát và quản lý ứng dụng một cách toàn diện mà không cần tự viết thêm code.
*   **Chức năng chính**: Cung cấp các HTTP Endpoints (hoặc JMX) để kiểm tra sức khỏe ứng dụng (`/health`), xuất chỉ số đo lường (`/metrics`), tích hợp hệ thống giám sát (`/prometheus`), xem cấu hình thực tế (`/env`, `/configprops`), và hỗ trợ gỡ lỗi production qua `/threaddump` hay `/heapdump`.
*   **Bản chất thực chiến**: Rất hữu ích cho DevOps/SRE nhưng là **con dao hai lưỡi**. Nếu không bảo mật đúng cách, Actuator có thể mở toang cánh cửa rò rỉ dữ liệu nhạy cảm (như mật khẩu DB, khóa API) cho hacker thông qua các endpoint xem cấu hình hoặc dump bộ nhớ.

## 🔍 Chi tiết bản chất thực chiến

### 1. Các Actuator Endpoints cốt lõi ứng dụng thực tế

| Endpoint | Chức năng chi tiết | Sử dụng thực chiến |
| :--- | :--- | :--- |
| **`/health`** | Hiển thị trạng thái sức khỏe của App và các kết nối (DB, Redis, Kafka...). | Làm probe (Liveness/Readiness) cho Kubernetes/Load Balancer. |
| **`/prometheus`**| Định dạng lại dữ liệu `/metrics` thành chuẩn Prometheus có thể đọc được. | Tích hợp hệ thống Prometheus + Grafana để vẽ Dashboard giám sát. |
| **`/env`** | Xem toàn bộ thuộc tính cấu hình môi trường đang chạy. | Kiểm tra các biến môi trường cấu hình thực tế của App. |
| **`/configprops`**| Xem các cấu hình gắn với class `@ConfigurationProperties`. | Kiểm tra tính chính xác của cấu hình Bean. |
| **`/threaddump`**| Liệt kê toàn bộ các Thread đang chạy và trạng thái khóa (Lock status). | Debug sự cố nghẽn luồng (Thread starvation, Deadlock) trên Production. |
| **`/heapdump`** | Tải về file Heap Dump nhị phân (.hprof) của toàn bộ JVM. | Phân tích Memory Leak bằng các công cụ như Eclipse Memory Analyzer (MAT). |

### 2. Sự khác biệt giữa Liveness Probe và Readiness Probe trong K8s dùng Actuator
Khi chạy ứng dụng trên Kubernetes, việc cấu hình chính xác `/health` là vô cùng quan trọng:
*   **Liveness Probe (Sự sống)**: Chỉ kiểm tra xem JVM của Java Application có còn hoạt động hay không. Nếu thất bại, K8s sẽ tiêu diệt và khởi động lại container.
    *   *Cấu hình Actuator*: `/actuator/health/liveness` (Chỉ check JVM status, không check DB/Redis vì nếu DB chết tạm thời, việc restart app liên tục sẽ làm nghẽn tải hệ thống vô ích).
*   **Readiness Probe (Sẵn sàng nhận tải)**: Kiểm tra xem ứng dụng đã khởi động xong và các kết nối cơ sở dữ liệu, hàng đợi đã sẵn sàng tiếp nhận traffic chưa. Nếu thất bại, K8s sẽ ngắt không cho traffic đi vào pod này nữa.
    *   *Cấu hình Actuator*: `/actuator/health/readiness` (Kiểm tra toàn bộ kết nối DB, Redis, Kafka, Downstream API).

## 💻 Code thực chiến: BAD vs GOOD

### ❌ BAD: Expose toàn bộ Endpoint ra bên ngoài mà không bảo mật
Mở toang tất cả các endpoint Actuator nhạy cảm và không giới hạn quyền truy cập trên Spring Security, cho phép bất kỳ ai cũng có thể gọi `/actuator/env` hay tải về `/actuator/heapdump` để trích xuất sạch toàn bộ dữ liệu mật của hệ thống.

```yaml
# application.yml (Cấu hình cực kỳ nguy hiểm!)
management:
  endpoints:
    web:
      exposure:
        # ❌ Phơi bày toàn bộ các endpoint ra môi trường web
        include: "*"
```

```java
package com.example.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfigBad {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                // ❌ Bỏ qua kiểm tra bảo mật cho toàn bộ đường dẫn actuator,
                // tạo sơ hở nghiêm trọng cho hacker quét thông tin hệ thống!
                .requestMatchers("/actuator/**").permitAll()
                .anyRequest().authenticated()
            );
        return http.build();
    }
}
```

### ✅ GOOD: Cấu hình phân tách, giới hạn Endpoint và phân quyền truy cập nghiêm ngặt
Chỉ phơi bày các endpoint thiết yếu nhất cho giám sát (`health` và `prometheus`), đồng thời khóa chặt và yêu cầu quyền `ADMIN` được bảo vệ bởi Basic Authentication hoặc mTLS đối với các endpoint gỡ lỗi nhạy cảm khác.

```yaml
# application.yml (Cấu hình an toàn chuẩn dự án lớn)
management:
  endpoints:
    web:
      exposure:
        # ✅ Chỉ cho phép phơi bày health và prometheus ra môi trường giám sát công khai
        include: "health, prometheus"
  endpoint:
    health:
      # ✅ Hiển thị chi tiết trạng thái DB/Redis nhưng chỉ khi được phân quyền truy cập
      show-details: when_authorized
      show-components: when_authorized
      probes:
        # ✅ Kích hoạt các probe liveness/readiness chuyên dụng cho Kubernetes
        enabled: true
```

```java
package com.example.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfigGood {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                // ✅ Cho phép public hai probe liveness/readiness phục vụ Kubernetes kiểm tra sức khỏe
                .requestMatchers("/actuator/health/liveness", "/actuator/health/readiness").permitAll()
                
                // ✅ Endpoint Prometheus cho hệ thống giám sát (chỉ cho mạng nội bộ hoặc hệ thống pull metrics)
                .requestMatchers("/actuator/prometheus").hasRole("MONITOR_SYSTEM")
                
                // ✅ Tất cả các endpoint quản trị/gỡ lỗi nhạy cảm khác bắt buộc phải là ADMIN truy cập
                .requestMatchers("/actuator/**").hasRole("ADMIN")
                
                .anyRequest().authenticated()
            )
            .httpBasic(Customizer.withDefaults()); // Sử dụng Basic Auth cho hệ thống Monitor tự động kết nối
            
        return http.build();
    }
}
```

## ⚠️ Common Gotchas & Questions follow-up

### 1. Cạm bẫy lộ thông tin nhạy cảm qua `/actuator/env` hoặc `/actuator/configprops`
Spring Boot có cơ chế tự động ẩn danh (Sanitization) các thông tin nhạy cảm (như thay đổi mật khẩu thành `******`).
*   *Mặc định*: Mọi thuộc tính có tên chứa từ khóa như `password`, `secret`, `key`, `token` sẽ bị che đi.
*   *Cạm bẫy thực chiến*: Nếu bạn đặt tên thuộc tính không theo các từ khóa mặc định này (ví dụ: `app.database.credential`), giá trị của nó sẽ bị phơi bày ở dạng text trần (plain-text) trên `/actuator/env`.
*   *Giải pháp*: Cấu hình thêm các pattern che dấu tùy chỉnh trong `application.yml`:
    ```yaml
    management:
      endpoint:
        env:
          keys-to-sanitize:
            - "*credential*"
            - "*pwd*"
    ```

### 2. Sự cố nghẽn tải Database do kubernetes check `/health` quá nhiều lần dưới tải lớn
Đây là sự cố hạ tầng cực kỳ đau đầu đối với các hệ thống Microservices quy mô lớn:
*   **Kịch bản**: Ứng dụng của bạn có kết nối Database. Kubernetes được cấu hình quét Readiness Probe vào endpoint `/actuator/health` cứ **5 giây/lần**. Khi bạn scale hệ thống lên **100 pods**, tổng số lượng request kiểm tra sức khỏe gửi tới App là cực lớn. Mỗi lần Actuator thực hiện kiểm tra health của Database, nó phải lấy ra 1 connection từ connection pool và thực hiện câu lệnh SQL kiểm tra (như `SELECT 1` hoặc `ping`).
*   **Hậu quả**: Dưới tải lớn, Database bị nghẽn (High CPU/Connection Exhausted) hoàn toàn chỉ vì phải xử lý hàng nghìn câu lệnh kiểm tra sức khỏe vô hại từ các pod!
*   **Giải pháp thực chiến**:
    1.  Tách biệt Liveness/Readiness Probe. Đặt tần suất quét liveness nhanh hơn (ví dụ 10s/lần) nhưng liveness **không truy vấn xuống DB**. Đặt tần suất quét readiness chậm hơn (ví dụ 30s/lần).
    2.  Sử dụng cơ chế **Cache** cho Health endpoint của Database bằng cấu hình:
        ```yaml
        management:
          endpoint:
            health:
              cache:
                time-to-live: 10s # Cache kết quả kiểm tra sức khỏe trong 10 giây
        ```
