# Production Issue Runbook — Impact → Stabilize → Evidence → Isolate → Fix → Prevent

## ⚡ Tóm tắt ngắn (30s)
* **Runbook framework cho production incident** chuẩn Senior:
  1. **Impact**: scope, severity, affected users.
  2. **Stabilize**: mitigate impact ngay (rollback, throttle, kill switch).
  3. **Evidence**: collect logs, metrics, traces.
  4. **Isolate**: root cause analysis.
  5. **Fix**: permanent solution.
  6. **Prevent**: postmortem, action items.
* **First 15 min critical**: communicate + contain.

---

## 🔍 6-step detail

### 1. Impact (5 min)
- Scope: # users, % traffic, regions.
- Severity: SEV-0 (full outage) to SEV-3 (minor).
- Business impact: revenue, customers, SLA breach.

### 2. Stabilize (15 min)
- Rollback recent deploy.
- Toggle feature flag.
- Throttle aggressive client.
- Failover to secondary.
- Goal: stop bleeding even if not fixed.

### 3. Evidence (30 min)
- Pull logs (errors before/during incident).
- Metrics (CPU, memory, p99 latency, error rate).
- Traces (slow / error spans).
- Recent changes (deploys, config).

### 4. Isolate (1-4 hours)
- Compare with baseline.
- Reproduce in staging.
- Bisect: find exact commit causing.
- Confirm hypothesis.

### 5. Fix (hours - days)
- Patch root cause.
- Test in staging.
- Gradual rollout.
- Verify metric back to normal.

### 6. Prevent (postmortem within 5 business days)
- Why this happened?
- Why not detected earlier?
- Action items: monitoring, test, runbook.

## ⚠️ Common Mistakes & Pro Tips

1. **Skip stabilize**: jump to fix → prolongs impact.
2. **Solo war room**: communicate with team early.
3. **No comms**: customers don't know status.
4. **Skip postmortem**: same issue happens again.
5. **Blame people**: focus on system, not individual.
6. **Document late**: real-time write down decisions.

**Senior pro tip**: practice answering "tell me about a production incident you handled" with this framework. Interviewer sees structured thinking.
