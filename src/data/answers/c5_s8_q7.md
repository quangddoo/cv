# Trade-off Context Window Lớn vs Retrieval Tốt

## ⚡ Tóm tắt ngắn (30s)
Refer c5_s1_q4.

* **Long context (200k+) win**: holistic reasoning cross-section, document analysis where info dispersed.
* **RAG (retrieval) win**: precise QA, multi-tenant ACL, knowledge update, cost-effective.
* **Default**: RAG. Long context for specific holistic tasks.
* **Hybrid**: agentic RAG = retrieve, then long-context analyze.

---

## 📊 Direct comparison

| Tiêu chí | Long context | RAG |
| :--- | :---: | :---: |
| Cost/request | $0.20-$2 | $0.005-$0.05 |
| Latency TTFT | 5-20s | 500ms-2s |
| Holistic reasoning | ✓ best | ✗ retrieval miss |
| Realtime update | ✓ | ✓ |
| Multi-tenant ACL | hard | ✓ filter |
| Lost in middle | risk | low |

## 💻 Hybrid: RAG → Long context

```java
public String answer(String q) {
    var chunks = rag.search(q, 5);
    
    if (needsHolisticView(q) && totalTokens(chunks) < 100_000) {
        // For "compare across all sections" — switch to long context
        var fullDoc = loadFullDoc(chunks.get(0).docId());
        return longContextLlm.chat(fullDoc + "\n\nQ: " + q);
    }
    return ragLlm.chat(buildContext(chunks) + "\n\nQ: " + q);
}
```

## ⚠️ Interviewer

**"User upload 200-page contract, ask 'find conflicting clauses'?"**
- This needs holistic view, RAG miss interaction between clauses.
- Use long context (Sonnet 200k or Gemini 1M).
- Cost: ~$0.50/contract. Justifiable for legal use case.
- Else: agentic RAG that retrieve all clauses → synthesize.
