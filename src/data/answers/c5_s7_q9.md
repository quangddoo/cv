# AI Response Format Sai làm Downstream Service Lỗi

## ⚡ Tóm tắt ngắn (30s)
* **Symptom**: downstream expects JSON schema, but LLM returns malformed → parsing error, cascade failures.
* **Causes**: prompt vague, model upgrade behavior diff, JSON mode not enabled, schema incomplete.
* **Quick fix**: enable JSON mode + retry with stricter prompt + fallback default.
* **Long-term**: structured output API + schema validation + retry logic + eval on format conformance.

---

## 🔍 Triage

### Step 1: Verify
- Sample malformed responses.
- Identify pattern: missing field? extra text? wrong type?

### Step 2: Quick fix
- Enable JSON mode if provider supports.
- Add retry with explicit schema in prompt.
- Fallback default for downstream.

### Step 3: Long-term
- Use provider structured output (OpenAI json_schema, Anthropic tool use).
- Schema validator layer.

## 💻 Structured output

```java
public TicketDecision classify(String email) {
    var schema = """
        {
          "type": "object",
          "properties": {
            "intent": {"enum": ["bug","feature","billing","other"]},
            "priority": {"enum": ["high","medium","low"]}
          },
          "required": ["intent","priority"]
        }
        """;
    
    try {
        return chatClient.prompt()
            .system("Output JSON conforming to schema. NO extra text.")
            .user(email)
            .options(ChatOptions.builder()
                .responseFormat(ResponseFormat.jsonSchema(schema))
                .temperature(0.0).build())
            .call()
            .entity(TicketDecision.class);
    } catch (JsonParseException e) {
        log.warn("Bad format, retry");
        return retryWithStricter(email);
    }
}
```

## 💻 Retry pattern

```java
private TicketDecision retryWithStricter(String email) {
    String response = chatClient.prompt()
        .system("Output ONLY valid JSON: {\"intent\":...,\"priority\":...}. No explanation.")
        .user(email)
        .call().content().trim();
    try {
        return mapper.readValue(response, TicketDecision.class);
    } catch (Exception e) {
        // Final fallback
        return new TicketDecision("other", "low");
    }
}
```

## 📊 Defense layers

| Layer | Effect |
| :--- | :--- |
| JSON mode native | 99%+ format compliance |
| Schema in prompt | Helps even without mode |
| Validate + retry | Catches edge cases |
| Default fallback | Graceful degradation |
| Monitor format errors | Detect drift |
