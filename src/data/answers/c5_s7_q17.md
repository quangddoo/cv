# Evaluation Pass nhưng User vẫn không Hài lòng

## ⚡ Tóm tắt ngắn (30s)
* **Phenomenon**: eval metrics good, but real users complain. Common.
* **Causes**:
  1. **Eval not representative**: golden set differs from real distribution.
  2. **Vanity metric**: measures wrong thing (e.g. accuracy when user wants speed).
  3. **Subjective quality**: tone, helpfulness not captured.
  4. **Edge cases**: long tail of unusual queries not in golden.
* **Action**:
  1. Survey users for specific complaints.
  2. Sample production traces, manual review.
  3. Identify gap: which slice of queries fails?
  4. Expand golden set with real failures.
  5. Re-design metrics if needed.

---

## 🔍 Investigation

### Step 1: Categorize complaints
- Type: wrong answer, too slow, tone, etc.
- Aggregate: which most frequent.

### Step 2: Sample production
- 100 random low-CSAT conversations.
- Manual annotation.

### Step 3: Compare with golden
- Does golden set cover these patterns?

### Step 4: Improve
- Add real failure cases to golden.
- Add metrics for subjective quality (LLM judge for helpfulness, tone).

        }
    }
