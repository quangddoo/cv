# Trade-off AI Personalization vs Data Privacy

## ⚡ Tóm tắt ngắn (30s)
* **Personalization**: better UX, higher conversion. Needs user data.
* **Privacy**: user trust, compliance. Limits data collection/use.
* **Solutions**:
  1. **Opt-in personalization**: user consent + transparency.
  2. **On-device computation** when possible.
  3. **Differential privacy / aggregation**.
  4. **Pseudonymization**: user ID = hash, not real ID to LLM.
  5. **Federated learning**: model trains on device, only aggregates shared.
* **Trade-off**:
  - Aggressive personalize: high CSAT, high privacy risk.
  - Minimal personalize: privacy safe, generic experience.

---

## 📊 Levels of personalization

| Level | Data used | Risk |
| :--- | :--- | :---: |
| None | None | None |
| Session | Current session only | Low |
| Tenant/role | Tenant + role aggregates | Low |
| Anonymous history | Hashed user behavior | Medium |
| Full PII personalize | Name, email, preferences | High |

## 💻 Opt-in personalization

```java
public String chat(String userId, String message) {
    UserPreference pref = userService.getPreference(userId);
    
    String prompt;
    if (pref.allowPersonalization()) {
        // Use user history (with consent)
        var history = userHistory.getRecent(userId, 10);
        prompt = buildPersonalizedPrompt(message, history, pref);
    } else {
        // Generic experience
        prompt = buildGenericPrompt(message);
    }
    
    return llm.chat(prompt);
}
```

## ⚠️ Interviewer

**"Customer wants right-to-be-forgotten for AI-trained data. Implementation?"**
1. Tag data per user; cascade delete when user deletes account.
2. Don't fine-tune on user data without consent.
3. RAG: delete user-uploaded docs.
4. Memory: delete personalization vectors.
5. Backup: document retention; pruning policy.
6. Audit: log deletion confirmation.
7. SLA: 30 days complete deletion.
