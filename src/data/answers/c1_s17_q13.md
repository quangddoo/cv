# Hiện thực hóa thuật toán băm nhất quán (Implement Consistent Hashing)

## ⚡ Tóm tắt ngắn (30s)
* **Bài toán**: Khi thiết kế hệ thống phân tán (Distributed Caching, Sharding Database), ta cần phân phối các khóa (Keys) đều cho $N$ máy chủ (Nodes). Nếu dùng phương pháp chia dư truyền thống (`hash(key) % N`): khi một máy chủ bị sập hoặc một máy mới được thêm vào ($N$ thay đổi), gần như **100% khóa sẽ bị ánh xạ sai vị trí**, gây ra cơn bão Cache Miss sập hệ thống.
* **Giải pháp Consistent Hashing (Băm nhất quán)**:
  1. Ánh xạ cả Máy chủ (Nodes) và Khóa (Keys) lên một vòng tròn số học (Hash Ring) có phạm vi từ $0$ đến $2^{32}-1$.
  2. Một khóa sẽ được xử lý bởi máy chủ đầu tiên xuất hiện khi đi **theo chiều kim đồng hồ** từ vị trí của khóa đó trên vòng tròn.
  3. **Nút ảo (Virtual Nodes)**: Để tránh phân bố không đều (Hot-spots), mỗi máy chủ vật lý được đại diện bằng nhiều nút ảo rải rác trên vòng tròn.
  4. Khi số lượng máy chủ thay đổi, chỉ có khoảng **$1/N$** số lượng khóa cần phải di chuyển vị trí lưu trữ.
* **Độ phức tạp**: Định vị máy chủ cho một khóa: $O(\log(N \times V))$ với $N$ là số node vật lý, $V$ là số nút ảo trên mỗi node.

---

## 🔍 Phân tích yêu cầu (Requirements)

### 1. Functional Requirements (Yêu cầu chức năng)
* Hỗ trợ động: Thêm máy chủ vật lý (`addNode`) và xóa máy chủ vật lý (`removeNode`).
* Định vị máy chủ phù hợp nhất cho một khóa bất kỳ (`getNode`).
* Cấu hình số lượng nút ảo (Virtual Nodes) linh hoạt để cân bằng tải tốt nhất.

### 2. Non-Functional Requirements (Yêu cầu phi chức năng)
* **Load Balance (Phân bổ đồng đều)**: Dữ liệu phải được dàn đều tối đa cho toàn bộ máy chủ, không xảy ra hiện tượng máy quá tải, máy trống rỗng (skewed data).
* **Minimal Remapping (Giảm thiểu tối đa việc dịch chuyển dữ liệu)**: Giảm thiểu số lượng khóa phải di chuyển khi hệ thống thực hiện Auto-scaling (Co giãn quy mô).
* **Độ trễ thấp**: Hàm định vị máy chủ (`getNode`) là hàm core được gọi liên tục cho mọi truy vấn nên phải hoạt động với hiệu suất cực cao (sử dụng cấu trúc dữ liệu tối ưu của Java).

## 🎨 Sơ đồ trực quan & Giải thuật

### 1. Khái niệm Vòng tròn băm (Hash Ring)

```
                       [ Node A#1 ] (Vị trí 100)
                     ▲             ▼
                  ▲                   ▼
    [ Key X ] ──► ●                    ● ◄── [ Node B#1 ] (Vị trí 1000)
  (Vị trí 400)  ▲                       ▼
               ▲                         ▼
               ▲                         ▼
                ▲                       ▼
                  ▲                   ▼
                     ▲             ▼
                       [ Node C#1 ] (Vị trí 2000)
```
* **Quy luật di chuyển**: Key X ở vị trí 400 đi theo chiều kim đồng hồ sẽ gặp Node B#1 ở vị trí 1000 trước tiên. Do đó Key X được phân phối cho máy chủ B.
* Nếu **Node B bị sập**: Chỉ những Keys nằm trong khoảng từ Node A đến Node B (trong đó có Key X) bị ảnh hưởng và được chuyển dịch tiếp theo chiều kim đồng hồ sang cho **Node C**. Các Keys khác thuộc Node C hay Node A giữ nguyên vị trí cũ!

## 💻 Code Example: Hiện thực hóa thuật toán bằng Java

Dưới đây là phiên bản hiện thực hóa cấu trúc dữ liệu Consistent Hashing hoàn chỉnh bằng Java. Chúng ta sử dụng `TreeMap` - cấu trúc dữ liệu dạng cây Đỏ-Đen (Red-Black Tree) để mô phỏng vòng tròn băm nhờ các phương thức tìm kiếm lân cận cực mạnh như `tailMap` và `firstKey`.

```java
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;
import java.util.*;

public class ConsistentHashRouter<T> {

    private final int numberOfReplicas; // Số lượng nút ảo (Virtual Nodes) cho mỗi Node vật lý
    
    // TreeMap đại diện cho Vòng tròn băm (Hash Ring)
    // Key: Vị trí băm trên vòng tròn (0 đến 2^32-1)
    // Value: Nút vật lý tương ứng
    private final TreeMap<Long, T> ring = new TreeMap<>();
    private final Map<String, Long> virtualNodePositions = new HashMap<>();

    public ConsistentHashRouter(int numberOfReplicas, Collection<T> nodes) {
        this.numberOfReplicas = numberOfReplicas;
        for (T node : nodes) {
            addNode(node);
        }
    }

    /**
     * Thêm một máy chủ vật lý mới vào Vòng tròn băm
     */
    public synchronized void addNode(T node) {
        for (int i = 0; i < numberOfReplicas; i++) {
            // Tạo định danh duy nhất cho nút ảo, ví dụ: "192.168.1.10#VN-0"
            String virtualNodeName = node.toString() + "#VN-" + i;
            if (virtualNodePositions.containsKey(virtualNodeName)) {
                continue; // Không đăng ký trùng cùng một node vật lý.
            }
            long hash = getHash(virtualNodeName);
            // Giải quyết collision bằng probing và lưu vị trí thực tế để removeNode()
            // xóa đúng virtual node đã thêm.
            while (ring.containsKey(hash)) {
                hash = (hash + 1) & 0xffffffffL;
            }
            ring.put(hash, node);
            virtualNodePositions.put(virtualNodeName, hash);
        }
    }

    /**
     * Xóa bỏ máy chủ vật lý ra khỏi Vòng tròn băm
     */
    public synchronized void removeNode(T node) {
        for (int i = 0; i < numberOfReplicas; i++) {
            String virtualNodeName = node.toString() + "#VN-" + i;
            Long hash = virtualNodePositions.remove(virtualNodeName);
            if (hash != null) {
                ring.remove(hash);
            }
        }
    }

    /**
     * Định vị nút vật lý phù hợp nhất xử lý cho Khóa
     */
    public synchronized T getNode(String key) {
        if (ring.isEmpty()) {
            return null;
        }
        long hash = getHash(key);
        
        // Nếu không có nút nào có hash lớn hơn hoặc bằng hash của khóa (tailMap rỗng)
        // Chúng ta vòng ngược lại lấy nút đầu tiên của vòng tròn (phương thức firstKey) (Gotcha 1)
        if (!ring.containsKey(hash)) {
            SortedMap<Long, T> tailMap = ring.tailMap(hash); // Lấy tập con các khóa >= hash hiện tại
            hash = tailMap.isEmpty() ? ring.firstKey() : tailMap.firstKey();
        }
        
        return ring.get(hash);
    }

    /**
     * Sử dụng thuật toán băm MD5 để băm chuỗi ký tự thành số nguyên 32-bit không âm (Long).
     * MD5 cho độ phân tán dữ liệu tốt hơn hàm hashCode() mặc định của Java rất nhiều.
     */
    private long getHash(String key) {
        try {
            MessageDigest md = MessageDigest.getInstance("MD5");
            byte[] digest = md.digest(key.getBytes(StandardCharsets.UTF_8));
            
            // Trích xuất 4 byte đầu tiên để tạo số nguyên 32-bit không âm
            long hash = ((long) (digest[3] & 0xFF) << 24)
                    | ((long) (digest[2] & 0xFF) << 16)
                    | ((long) (digest[1] & 0xFF) << 8)
                    | ((long) (digest[0] & 0xFF));
            return hash & 0xffffffffL; // Đảm bảo số dương
        } catch (NoSuchAlgorithmException e) {
            // Fallback sang MurmurHash hoặc HashCode cơ bản nếu không tìm thấy thuật toán MD5
            return Math.abs((long) key.hashCode());
        }
    }

    // --- Hàm Demo hoạt động ---
    public static void main(String[] args) {
        // Khởi tạo 3 máy chủ vật lý ban đầu
        List<String> servers = new ArrayList<>(Arrays.asList("Server-A", "Server-B", "Server-C"));
        
        // Cấu hình 150 nút ảo cho mỗi máy chủ để cân bằng tải tốt nhất
        ConsistentHashRouter<String> router = new ConsistentHashRouter<>(150, servers);

        // Giả lập phân phối 10 khóa dữ liệu
        System.out.println("--- PHÂN PHỐI KHÓA BAN ĐẦU ---");
        Map<String, String> keyMapping = new HashMap<>();
        for (int i = 0; i < 10; i++) {
            String key = "user_session_id_" + (1000 + i);
            String targetNode = router.getNode(key);
            keyMapping.put(key, targetNode);
            System.out.printf("Khóa: %-25s ===> Gửi tới: %s\n", key, targetNode);
        }

        // Tình huống: Thêm máy chủ Server-D vào hệ thống
        System.out.println("\n--- TÌNH HUỐNG: THÊM SERVER-D VÀO HỆ THỐNG ---");
        router.addNode("Server-D");
        
        int migratedKeysCount = 0;
        for (String key : keyMapping.keySet()) {
            String newTargetNode = router.getNode(key);
            if (!newTargetNode.equals(keyMapping.get(key))) {
                System.out.printf("Khóa [%s] đã di chuyển: %s ===> %s\n", key, keyMapping.get(key), newTargetNode);
                migratedKeysCount++;
            }
        }
        System.out.printf("Kết luận: Chỉ có %d/%d khóa cần phải di chuyển dữ liệu (Tối ưu cực lớn!)\n", 
                          migratedKeysCount, keyMapping.size());
    }
}
```

## 📊 Phân tích độ phức tạp & Trade-offs

### So sánh băm truyền thống và băm nhất quán

| Tiêu chí | Băm truyền thống (`hash(key) % N`) | Băm nhất quán (Consistent Hashing) |
| :--- | :--- | :--- |
| **Độ trễ truy xuất máy chủ (`getNode`)**| **$O(1)$**: Siêu nhanh nhờ phép toán học cơ bản. | **$O(\log(N \times V))$**: Cực nhanh, sử dụng tìm kiếm nhị phân trên cây đỏ đen TreeMap. |
| **Hậu quả khi co giãn hệ thống (Thêm/Xóa Node)** | **Thảm họa**: Dữ liệu gần như bị tráo đổi hoàn toàn (remap $\approx 99\%$). Gây sập các tầng dữ liệu phía dưới. | **Tối ưu**: Chỉ di chuyển $\approx 1/N$ tổng số lượng khóa hiện tại. Bảo vệ an toàn tuyệt đối các tầng Backend. |
| **Cân bằng tải dữ liệu (Load Distribution)** | Tốt nếu hàm băm đều. | Cực kỳ tốt nhờ sự hỗ trợ đắc lực từ cơ chế **Nút ảo (Virtual Nodes)** giúp chia cắt vòng tròn mịn hơn. |
| **Bộ nhớ sử dụng** | $O(1)$: Không tốn thêm bộ nhớ lưu trữ trung gian. | $O(N \times V)$: Cần duy trì bộ nhớ lưu trữ các nút ảo trên vòng tròn băm. |

## ⚠️ Common Gotchas (Câu hỏi đào sâu từ interviewer)

### 1. Tại sao cơ chế Nút ảo (Virtual Nodes) lại vô cùng quan trọng? Nếu không dùng nút ảo thì hệ thống gặp vấn đề gì?
* **Trả lời**: Đây là câu hỏi kinh điển về thiết kế phân bố:
  * **Vấn đề phân bố tự nhiên**: Khi chúng ta băm các node vật lý thô trực tiếp lên vòng tròn (ví dụ chỉ có 3 node Server-A, B, C), rất có khả năng vị trí băm của 3 máy này sẽ rơi vào rất sát nhau trên vòng tròn. Việc này tạo ra các khoảng trống khổng lồ chiếm tới 80-90% vòng tròn băm. Điều này dẫn đến một máy chủ phải gánh chịu 90% lượng request, trong khi các máy còn lại rảnh rỗi hoàn toàn, tạo nên hiện tượng **Hot-spot (Điểm nóng quá tải)**.
  * **Giải pháp Nút ảo**: Bằng cách nhân bản mỗi nút vật lý lên $V$ lần (ví dụ $V=150$, tức 150 nút ảo rải đều ngẫu nhiên rải rác khắp ngõ ngách vòng tròn), vòng tròn được chia nhỏ thành hàng ngàn cung tròn siêu nhỏ đan xen nhau. Nhờ định luật số lớn của xác suất thống kê, tải trọng được san bằng đều tăm tắp cho tất cả máy chủ vật lý.

### 2. Làm thế nào để giải quyết vấn đề bất đối xứng cấu hình phần cứng giữa các máy chủ vật lý? (Ví dụ: Server-A có 64GB RAM, Server-B chỉ có 16GB RAM)
* **Trả lời**: Thuật toán băm nhất quán giải quyết bài toán này cực kỳ linh hoạt thông qua khái niệm **Trọng số nút ảo (Weighted Virtual Nodes)**:
  * Thay vì gán một hằng số nút ảo cố định cho tất cả các máy chủ vật lý, ta thiết lập số lượng nút ảo tỉ lệ thuận với hiệu năng phần cứng của máy chủ đó:
    * Server-A (64GB RAM - Khỏe gấp 4 lần): Gán $4 \times 150 = 600$ nút ảo.
    * Server-B (16GB RAM): Chỉ gán $1 \times 150 = 150$ nút ảo.
  * Nhờ số lượng nút ảo rải trên vòng tròn nhiều gấp 4 lần, Server-A sẽ tự động nhận diện và gánh vác lượng Session/Khóa gấp 4 lần Server-B một cách hoàn toàn tự nhiên và chính xác!

### 3. Tại sao chúng ta sử dụng thuật toán MD5 để băm thay vì hàm `String.hashCode()` mặc định của Java?
* **Trả lời**: 
  * Hàm `hashCode()` mặc định của Java có phạm vi phân bổ phân bố ngẫu nhiên khá kém và dễ xảy ra xung đột băm (Hash Collision) do thuật toán nhân số nguyên tố 31 đơn giản. Điều này làm cho các khóa ảo dễ tụ tập gần nhau.
  * Các thuật toán băm mật mã như **MD5, SHA-256** hoặc hàm băm chuyên dụng phi mật mã như **MurmurHash3** được tối ưu hóa toán học để đảm bảo **Tính chất tuyết lở (Avalanche Effect)**: chỉ một thay đổi cực nhỏ ở đầu vào cũng tạo ra một mã băm đầu ra hoàn toàn khác biệt và phân tán cực đều trên dải số nguyên 32-bit, giúp tối ưu hóa việc phân chia cung tròn băm.
