# Failure Thinking — "If X Fails, Then What?"

## ⚡ Tóm tắt ngắn (30s)
* **Failure thinking** = mỗi component trong design, ask "what if it fails?". Then design for failure.
* **Standard failures**:
  1. Network partition / timeout.
  2. Service crash / restart.
  3. Database failover.
  4. Cache miss / poison.
  5. Message queue lag / loss.
  6. Disk full.
  7. Memory leak / OOM.
  8. CPU saturated.
  9. Provider outage.
  10. Human error (bad deploy).
* **Mindset**: every step in flow has fail mode. Design recovery.

---

## 🔍 Practice: walk through design and ask

```
"Our service calls DB. What if DB fails?"
  → Connection timeout → retry → circuit breaker → fallback (cache, error).

"What if Kafka producer fails?"
  → Local persistent queue → retry → DLQ.

"What if downstream API rate-limits us?"
  → Retry with backoff → circuit → degrade service.

"What if our pod restarts mid-transaction?"
  → Saga compensation → idempotent processing → state recovery.

"What if we deploy bad code at 2am?"
  → Canary rollout → auto-rollback → kill switch.
```

---

## 💻 Failure annotation in design

When designing, annotate each arrow:
```
[Service A] --(retry 3x, timeout 5s, circuit)--> [Service B]
```

State assumptions about failure handling EXPLICIT.

## 📊 Failure checklist per component

| Component | Possible failures | Handling |
| :--- | :--- | :--- |
| DB | Down, slow, full | Connection pool, retry, replica, archive |
| Cache | Miss, evict, stale | Fallback DB, TTL, invalidate |
| Queue | Lag, full, lost | Backpressure, persistence, DLQ |
| External API | Down, rate limit, slow | Circuit, retry, cache, fallback |
| Pod | Crash, restart, OOM | Idempotency, graceful shutdown, HPA |
| Network | Partition, latency | Timeout, retry, multi-AZ |
| Deploy | Bad code | Canary, rollback, kill switch |

---

## ⚠️ Common Mistakes & Pro Tips

1. **Happy path only**: design works in best case.
2. **Cascade failure**: one fail brings everything down.
3. **No graceful degrade**: all-or-nothing.
4. **Missing observability**: failure happens silently.

**Pro tip**: when presenting design, proactively say "if this component fails, here's the fallback". Interviewer impressed by failure-thinking maturity.
