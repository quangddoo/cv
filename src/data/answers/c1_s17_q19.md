# Các biến thể của tìm kiếm nhị phân (Binary Search Variations)

## ⚡ Tóm tắt ngắn (30s)
* **Bài toán**: Thuật toán tìm kiếm nhị phân truyền thống chỉ đơn thuần tìm xem phần tử `target` có tồn tại trong mảng đã sắp xếp hay không. Trong phỏng vấn thực tế, các biến thể phức tạp hơn thường xuyên được hỏi:
  1. **Tìm vị trí đầu tiên (First Occurrence)** của một số có nhiều phần tử trùng lặp.
  2. **Tìm vị trí cuối cùng (Last Occurrence)** của số đó.
  3. **Tìm kiếm trên mảng đã xoay vòng (Search in Rotated Sorted Array)** (ví dụ: `[4, 5, 6, 7, 0, 1, 2]`).
* **Giải pháp cốt lõi**:
  * **First Occurrence**: Khi gặp `nums[mid] == target`, ghi nhận kết quả tạm thời và tiếp tục co hẹp không gian tìm kiếm sang bên trái: `right = mid - 1`.
  * **Last Occurrence**: Khi gặp `nums[mid] == target`, ghi nhận kết quả và tiếp tục tìm kiếm sang bên phải: `left = mid + 1`.
  * **Rotated Array**: Xác định xem nửa bên trái hay nửa bên phải của `mid` đang được sắp xếp chuẩn. Sau đó kiểm tra xem `target` có rơi vào phạm vi của nửa được sắp xếp đó không để định hướng thu hẹp phạm vi tìm kiếm.
* **Độ phức tạp**: Thời gian $O(\log N)$ cực tối ưu nhờ chia đôi liên tục, không gian $O(1)$ bổ sung.

## 🔍 Phân tích yêu cầu (Requirements)

### 1. Functional Requirements (Yêu cầu chức năng)
* Tìm vị trí xuất hiện đầu tiên/cuối cùng của phần tử trùng lặp (trả về `-1` nếu không có).
* Tìm kiếm chính xác phần tử trong mảng bị xoay vòng tại một điểm neo ẩn (pivot) mà không cần sắp xếp lại mảng.

### 2. Non-Functional Requirements (Yêu cầu phi chức năng)
* **Tránh tràn số (Integer Overflow Prevention)**: Cách tính chỉ số giữa `mid` phải an toàn tuyệt đối trước nguy cơ tràn số nguyên trong Java.
* **Tránh vòng lặp vô hạn (Infinite Loop Prevention)**: Thiết lập điều kiện biên dịch chuyển `left` và `right` chuẩn xác để tránh trường hợp thuật toán bị kẹt vĩnh viễn (khi `left` và `right` đứng sát nhau).

## 🎨 Sơ đồ trực quan & Bản chất toán học

### 1. Cơ chế tính chỉ số `mid` an toàn chống tràn số

Công thức toán học cơ bản để tính điểm giữa:
$$\text{mid} = \frac{\text{left} + \text{right}}{2}$$

> [!WARNING]
> **Rủi ro tràn số**: Nếu `left` và `right` có giá trị lớn gần với $2^{31}-1$ (giới hạn của kiểu dữ liệu `int` trong Java), phép cộng $\text{left} + \text{right}$ sẽ vượt quá giới hạn và sinh ra một số âm, dẫn đến lỗi chỉ mục âm `ArrayIndexOutOfBoundsException`.

**Công thức thay thế an toàn tuyệt đối**:
$$\text{mid} = \text{left} + \frac{\text{right} - \text{left}}{2}$$

---

### 2. Ý tưởng tìm kiếm trên Mảng xoay vòng (Rotated Sorted Array)

Mảng: `[4, 5, 6, 7, 0, 1, 2]` chia đôi tại `mid = 3` (giá trị là 7).
* **Nửa bên trái** `[4, 5, 6, 7]`: Được sắp xếp tăng dần hoàn hảo (vì `nums[left] <= nums[mid]` -> `4 <= 7`).
* **Nửa bên phải** `[7, 0, 1, 2]`: Bị xoay vòng (không được sắp xếp đều).
* **Quy luật trượt**: Ta luôn xác định được một nửa mảng sắp xếp chuẩn để đối chiếu phạm vi của `target`. Từ đó đưa ra quyết định di chuyển thông minh.

## 💻 Code Example: Hiện thực hóa các biến thể bằng Java

Dưới đây là mã nguồn Java hoàn chỉnh, hiện thực hóa tối ưu 3 biến thể tìm kiếm nhị phân hàng đầu, tuân thủ nghiêm ngặt nguyên tắc an toàn số học và quản lý điều kiện biên chặt chẽ:

```java
public class BinarySearchVariations {

    /**
     * Biến thể 1: Tìm chỉ mục xuất hiện ĐẦU TIÊN (First Occurrence) của target
     */
    public int findFirstOccurrence(int[] nums, int target) {
        if (nums == null || nums.length == 0) return -1;

        int left = 0;
        int right = nums.length - 1;
        int result = -1; // Biến ghi nhận chỉ mục kết quả tốt nhất

        while (left <= right) {
            // Tính toán mid an toàn chống tràn số nguyên (Gotcha 1)
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                result = mid; // Tạm ghi nhận vị trí khớp hiện tại
                right = mid - 1; // Tiếp tục ép dải tìm kiếm sang trái xem có vị trí nào sớm hơn không
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return result;
    }

    /**
     * Biến thể 2: Tìm chỉ mục xuất hiện CUỐI CÙNG (Last Occurrence) của target
     */
    public int findLastOccurrence(int[] nums, int target) {
        if (nums == null || nums.length == 0) return -1;

        int left = 0;
        int right = nums.length - 1;
        int result = -1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                result = mid; // Tạm ghi nhận
                left = mid + 1; // Tiếp tục ép dải tìm kiếm sang phải để tìm vị trí muộn hơn
            } else if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return result;
    }

    /**
     * Biến thể 3: Tìm kiếm trên Mảng đã được xoay vòng (Rotated Sorted Array)
     */
    public int searchInRotatedArray(int[] nums, int target) {
        if (nums == null || nums.length == 0) return -1;

        int left = 0;
        int right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                return mid;
            }

            // Trường hợp 1: Nửa bên trái của mid đang được sắp xếp chuẩn
            if (nums[left] <= nums[mid]) {
                // Kiểm tra xem target có nằm trong dải giá trị của nửa trái hay không
                if (target >= nums[left] && target < nums[mid]) {
                    right = mid - 1; // Thu hẹp tìm kiếm về bên trái
                } else {
                    left = mid + 1;  // Tìm kiếm bên phải
                }
            } 
            // Trường hợp 2: Nửa bên phải của mid đang được sắp xếp chuẩn
            else {
                // Kiểm tra xem target có nằm trong dải giá trị của nửa phải hay không
                if (target > nums[mid] && target <= nums[right]) {
                    left = mid + 1;  // Thu hẹp tìm kiếm về bên phải
                } else {
                    right = mid - 1; // Tìm kiếm bên trái
                }
            }
        }
        return -1;
    }

    // --- Hàm Demo chạy thử ---
    public static void main(String[] args) {
        BinarySearchVariations solver = new BinarySearchVariations();

        // Thử nghiệm biến thể 1 & 2
        int[] sortedWithDuplicates = {1, 2, 2, 2, 3, 4, 5};
        System.out.println("Mảng trùng lặp: [1, 2, 2, 2, 3, 4, 5]");
        System.out.println("Vị trí ĐẦU TIÊN của số 2: " + solver.findFirstOccurrence(sortedWithDuplicates, 2)); // 1
        System.out.println("Vị trí CUỐI CÙNG của số 2: " + solver.findLastOccurrence(sortedWithDuplicates, 2));  // 3

        // Thử nghiệm biến thể 3
        int[] rotatedArray = {4, 5, 6, 7, 0, 1, 2};
        System.out.println("\nMảng xoay vòng: [4, 5, 6, 7, 0, 1, 2]");
        System.out.println("Tìm kiếm số 0: Vị trí thứ " + solver.searchInRotatedArray(rotatedArray, 0)); // 4
        System.out.println("Tìm kiếm số 5: Vị trí thứ " + solver.searchInRotatedArray(rotatedArray, 5)); // 1
    }
}
```

## 📊 Phân tích độ phức tạp & Trade-offs

### So sánh các kỹ thuật tìm kiếm

| Giải pháp | Tìm kiếm tuần tự (Linear Search) | Sắp xếp lại rồi tìm kiếm nhị phân | Tìm kiếm nhị phân trên mảng xoay vòng trực tiếp |
| :--- | :--- | :--- | :--- |
| **Độ phức tạp thời gian** | **Kém**: $O(N)$ do phải duyệt qua từng phần tử một từ trái qua phải. | **Rất kém**: $O(N \log N)$ để sắp xếp mảng trước, cộng thêm $O(\log N)$ để tìm. | **Tuyệt vời**: $O(\log N)$ nhờ kỹ thuật chia đôi không gian tìm kiếm trực tiếp trên cấu trúc cũ. |
| **Độ phức tạp bộ nhớ** | **Tối ưu nhất**: $O(1)$ không tốn thêm bộ nhớ. | **Kém**: Đòi hỏi $O(N)$ hoặc $O(\log N)$ bộ nhớ phụ trợ trong lúc sắp xếp. | **Tối ưu nhất**: $O(1)$ thực hiện co con trỏ ngay tại chỗ (In-place). |
| **Tính ứng dụng thực tế** | Chỉ thích hợp với mảng kích thước nhỏ không có cấu trúc. | Thao tác ghi dữ liệu đắt đỏ, phá vỡ cấu trúc thứ tự ban đầu của mảng. | **Cực tốt** cho các hệ thống lưu trữ phân tán dạng Log-Structured Merge-tree (như Cassandra, BigTable) nơi dữ liệu có cấu trúc xoay vòng. |

## ⚠️ Common Gotchas (Câu hỏi đào sâu từ interviewer)

### 1. Tại sao trong tìm kiếm nhị phân, điều kiện dừng vòng lặp lại là `while (left <= right)` thay vì `while (left < right)`? Lỗi gì có thể xảy ra?
* **Trả lời**: Đây là một chi tiết cực kỳ tinh tế kiểm tra sự tỉ mỉ của ứng viên:
  * **Lý do dùng `<= (Nhỏ hơn hoặc bằng)`**: 
    * Giả sử mảng chỉ chứa 1 phần tử duy nhất: `nums = [5]`, và ta tìm kiếm `target = 5`. Lúc này `left = 0`, `right = 0`.
    * Nếu ta đặt điều kiện là `left < right` (0 < 0 là Sai), vòng lặp `while` sẽ **không bao giờ được thực thi**, và thuật toán trả về kết quả `-1` (Sai hoàn toàn!).
    * Sử dụng `<=`, vòng lặp sẽ thực thi tại thời điểm `left == right`, tính toán `mid = 0`, so sánh `nums[0] == 5` khớp và trả về chỉ mục 0 chính xác.
  * **gotcha bổ sung**: Khi sử dụng `<=`, ta bắt buộc phải dịch chuyển biên một cách triệt để thông qua `left = mid + 1` và `right = mid - 1`. Nếu ta đặt `right = mid` hoặc `left = mid`, thuật toán sẽ lập tức bị rơi vào **vòng lặp vô hạn (Infinite Loop)** khi `left` đứng cạnh `right` (ví dụ: `left = 0, right = 1`).

### 2. Làm thế nào để giải quyết bài toán mảng xoay vòng chứa các PHẦN TỬ TRÙNG LẶP (ví dụ: `nums = [1, 0, 1, 1, 1]`)? Có duy trì được độ phức tạp $O(\log N)$ không?
* **Trả lời**:
  * **Thực trạng**: Khi mảng xoay vòng chứa phần tử trùng lặp, ta có thể gặp tình huống: `nums[left] == nums[mid] == nums[right]` (như trong mảng `[1, 0, 1, 1, 1]` với `mid = 2` giá trị 1). Lúc này, thuật toán hoàn toàn **bị mất phương hướng**, không thể xác định nổi nửa bên nào đang được sắp xếp đều để đối chiếu.
  * **Cách giải quyết**: Ta bắt buộc phải thực hiện bước co hẹp biên một cách thủ công từng bước một để phá vỡ thế bế tắc:
    ```java
    if (nums[left] == nums[mid] && nums[mid] == nums[right]) {
        left++;
        right--;
    }
    ```
  * **Độ phức tạp**: Do có trường hợp phải dịch chuyển tuyến tính từng phần tử (`left++`, `right--`), độ phức tạp thời gian trong trường hợp xấu nhất (Worst-case) sẽ bị suy thoái từ $O(\log N)$ về **$O(N)$**. Đây là giới hạn toán học không thể vượt qua!

### 3. Phương pháp Binary Search có thể áp dụng trên cấu trúc danh sách liên kết (LinkedList) đã được sắp xếp hay không? Tại sao?
* **Trả lời**:
  * **Về mặt kỹ thuật**: Có thể áp dụng được, nhưng **không có giá trị thực tế**.
  * **Giải thích**: Ưu thế tuyệt đối của tìm kiếm nhị phân dựa trên khả năng truy xuất chỉ số ngẫu nhiên trong thời gian hằng số $O(1)$ của mảng (Random Access). Trên LinkedList, để truy cập đến phần tử ở vị trí giữa `mid`, ta bắt buộc phải duyệt tuyến tính từ đầu danh sách mất thời gian $O(K)$. Việc này làm độ phức tạp tổng thể bị kéo lên thành $O(N \log N)$ - tệ hơn cả tìm kiếm tuần tự thông thường $O(N)$!
