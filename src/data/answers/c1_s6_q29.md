# Global Exception Handling bằng @ControllerAdvice: Chuẩn hóa phản hồi lỗi hệ thống

## ⚡ Tóm tắt ngắn (30s)
Cơ chế xử lý lỗi tập trung (**Global Exception Handling**) trong Spring Boot sử dụng **`@RestControllerAdvice`** và **`@ExceptionHandler`** là giải pháp kiến trúc tối ưu để chuẩn hóa phản hồi lỗi.
*   **Bản chất**: Thay vì bắt lỗi thủ công bằng khối `try-catch` ở từng Controller (làm rối mã nguồn), mọi ngoại lệ (Exception) quăng lên từ Controller hoặc Service sẽ được gom lại và xử lý tại một lớp trung tâm.
*   **Đầu ra chuẩn**: Giúp hệ thống luôn trả về phản hồi lỗi dạng JSON thống nhất (bao gồm: mã trạng thái HTTP, mã lỗi nội bộ - Error Code, thông điệp rõ ràng, danh sách chi tiết lỗi validate, và Correlation ID để tra cứu log).
*   **An toàn bảo mật**: Ngăn chặn hoàn toàn việc rò rỉ vết lỗi hệ thống (Stack Trace, cấu trúc DB) ra môi trường bên ngoài.

## 🔍 Chi tiết bản chất thực chiến

### 1. Luồng đi của Exception dưới mui xe
Khi một lỗi xảy ra trong luồng xử lý của ứng dụng:
```text
 [ Request ] ──> [ DispatcherServlet ] ──> [ Controller ] (Xảy ra lỗi!)
                        │                                  │
                        │                                  ▼
                        │                      [ Quăng Exception lên trên ]
                        │                                  │
                        │<─────────────────────────────────┘
                        │
             [ HandlerExceptionResolver ]
                        │
                        ├─(Được cấu hình bởi `@RestControllerAdvice`)─> [ ExceptionHandlerExceptionResolver ]
                        │                                                        │
                        │                                                        ▼
                        │                                             [ Khớp @ExceptionHandler ]
                        │                                                        │
                        │                                                        ▼
                        │                                              [ Thực thi logic xử lý ]
                        │                                                        │
                        │<─── Gửi lại phản hồi JSON chuẩn hóa ───────────────────┘
 [ Response JSON ] <────┘
```

### 2. Thiết kế Cấu trúc JSON lỗi chuẩn dự án lớn (Production-ready)
Một cấu trúc dữ liệu lỗi chuẩn chỉnh không bao giờ được phép gửi trực tiếp Stack Trace hay Message thô của Java. Nó cần bao gồm các thông tin thiết yếu sau:
*   `timestamp`: Thời điểm xảy ra lỗi.
*   `status`: HTTP Status Code tương ứng (ví dụ: 400, 404, 500).
*   `errorCode`: Mã lỗi nghiệp vụ riêng của hệ thống (ví dụ: `USER_NOT_FOUND`, `INSUFFICIENT_BALANCE`). Rất quan trọng để ứng dụng di động/Frontend dịch ngôn ngữ hiển thị.
*   `message`: Thông điệp mô tả ngắn gọn lỗi dành cho lập trình viên Frontend đọc.
*   `details`: Mảng chi tiết các trường bị lỗi (đặc biệt quan trọng đối với lỗi validate form đầu vào).
*   `path`: Endpoint xảy ra lỗi.
*   `traceId`: Mã định danh yêu cầu (Correlation ID) được sinh ra từ Gateway để DevOps đối chiếu, lục vết log trong các hệ thống lớn (ELK, Datadog).

## 💻 Code thực chiến: BAD vs GOOD

### ❌ BAD: Trả về Stack Trace thô hoặc tự bắt lỗi thủ công ở mỗi Controller
Controller bị phình to bởi hàng tá khối try-catch, trả về thông điệp lỗi dạng text trần không đồng nhất hoặc nguy hiểm hơn là ném nguyên Stack Trace hệ thống chứa thông tin nhạy cảm về Database/Server cho Client.

```java
package com.example.controller;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import com.example.service.UserService;

@RestController
@RequestMapping("/api/users")
public class UserControllerBad {

    private final UserService userService;

    public UserControllerBad(UserService userService) {
        this.userService = userService;
    }

    @GetMapping("/{id}")
    public ResponseEntity<?> getUserById(@PathVariable Long id) {
        try {
            return ResponseEntity.ok(userService.findById(id));
        } catch (Exception e) {
            // ❌ Lỗi 1: Tự viết try-catch thủ công lặp lại ở mọi API
            // ❌ Lỗi 2: Trả về e.getMessage() chứa thông tin nhạy cảm của Database
            // ❌ Lỗi 3: Không có cấu trúc JSON lỗi chuẩn hóa
            return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                    .body("Error: " + e.getMessage()); 
        }
    }
}
```

### ✅ GOOD: Triển khai Mô hình RestControllerAdvice chuẩn hóa toàn hệ thống

#### Bước 1: Định nghĩa đối tượng phản hồi lỗi chuẩn (`ErrorResponse.java`)
```java
package com.example.exception;

import com.fasterxml.jackson.annotation.JsonInclude;
import lombok.Builder;
import lombok.Data;
import java.time.LocalDateTime;
import java.util.List;

@Data
@Builder
@JsonInclude(JsonInclude.Include.NON_NULL) // Ẩn các trường null để giữ JSON sạch sẽ
public class ErrorResponse {
    private LocalDateTime timestamp;
    private int status;
    private String errorCode;
    private String message;
    private String path;
    private String traceId; // Correlation ID phục vụ tra cứu log
    private List<ValidationError> errors; // Chi tiết lỗi validation

    @Data
    @Builder
    public static class ValidationError {
        private String field;
        private String rejectedValue;
        private String message;
    }
}
```

#### Bước 2: Định nghĩa các Custom Exception nghiệp vụ
```java
package com.example.exception;

import lombok.Getter;

@Getter
public class ResourceNotFoundException extends RuntimeException {
    private final String errorCode;

    public ResourceNotFoundException(String message, String errorCode) {
        super(message);
        this.errorCode = errorCode;
    }
}
```

#### Bước 3: Viết lớp xử lý trung tâm (`GlobalExceptionHandler.java`)
```java
package com.example.exception;

import jakarta.servlet.http.HttpServletRequest;
import lombok.extern.slf4j.Slf4j;
import org.slf4j.MDC;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import java.time.LocalDateTime;
import java.util.List;
import java.util.stream.Collectors;

@Slf4j
@RestControllerAdvice // ✅ Kết hợp @ControllerAdvice và @ResponseBody
public class GlobalExceptionHandler {

    private static final String TRACE_ID_HEADER = "X-Trace-Id";

    // ✅ 1. Bắt ngoại lệ nghiệp vụ cụ thể (Resource Not Found)
    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleResourceNotFound(ResourceNotFoundException ex, HttpServletRequest request) {
        log.warn("Resource not found: {}", ex.getMessage());
        
        ErrorResponse error = ErrorResponse.builder()
                .timestamp(LocalDateTime.now())
                .status(HttpStatus.NOT_FOUND.value())
                .errorCode(ex.getErrorCode())
                .message(ex.getMessage())
                .path(request.getRequestURI())
                .traceId(MDC.get(TRACE_ID_HEADER)) // Lấy Correlation ID từ bộ nhớ MDC
                .build();
                
        return new ResponseEntity<>(error, HttpStatus.NOT_FOUND);
    }

    // ✅ 2. Bắt ngoại lệ Validate dữ liệu đầu vào (DTO Validation)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidationException(MethodArgumentNotValidException ex, HttpServletRequest request) {
        log.warn("Validation failed for request: {}", request.getRequestURI());

        // Lấy danh sách các lỗi trường cụ thể
        List<ErrorResponse.ValidationError> validationErrors = ex.getBindingResult()
                .getFieldErrors()
                .stream()
                .map(fieldError -> ErrorResponse.ValidationError.builder()
                        .field(fieldError.getField())
                        .rejectedValue(String.valueOf(fieldError.getRejectedValue()))
                        .message(fieldError.getDefaultMessage())
                        .build())
                .collect(Collectors.toList());

        ErrorResponse error = ErrorResponse.builder()
                .timestamp(LocalDateTime.now())
                .status(HttpStatus.BAD_REQUEST.value())
                .errorCode("VALIDATION_FAILED")
                .message("Dữ liệu đầu vào không hợp lệ!")
                .path(request.getRequestURI())
                .traceId(MDC.get(TRACE_ID_HEADER))
                .errors(validationErrors)
                .build();

        return new ResponseEntity<>(error, HttpStatus.BAD_REQUEST);
    }

    // ✅ 3. Chốt chặn bảo mật cuối cùng cho các Exception chưa được định nghĩa trước
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleGenericException(Exception ex, HttpServletRequest request) {
        // Ghi lại Stack Trace đầy đủ ở log hệ thống để lập trình viên gỡ lỗi
        log.error("Internal Server Error occurred at path: {}", request.getRequestURI(), ex);

        ErrorResponse error = ErrorResponse.builder()
                .timestamp(LocalDateTime.now())
                .status(HttpStatus.INTERNAL_SERVER_ERROR.value())
                .errorCode("INTERNAL_SERVER_ERROR")
                // ✅ Che dấu lỗi thô, chỉ trả về thông báo an toàn, thân thiện
                .message("Đã xảy ra sự cố hệ thống ngoài ý muốn. Vui lòng liên hệ quản trị viên!")
                .path(request.getRequestURI())
                .traceId(MDC.get(TRACE_ID_HEADER))
                .build();

        return new ResponseEntity<>(error, HttpStatus.INTERNAL_SERVER_ERROR);
    }
}
```

## ⚠️ Common Gotchas & Questions follow-up

### 1. Sự phân cấp kế thừa và thứ tự xử lý lỗi (Order of @ExceptionHandler)
Đây là lỗi cấu hình tiềm ẩn khiến hệ thống hoạt động không đúng như mong đợi:
*   **Cạm bẫy**: Bạn khai báo hai phương thức xử lý lỗi trong cùng một RestControllerAdvice: một phương thức bắt `RuntimeException.class` và một phương thức bắt `ResourceNotFoundException.class`. Nếu bạn không cẩn thận đặt phương thức bắt lớp cha (`RuntimeException`) ở vị trí sai hoặc cấu hình chồng chéo, Spring có thể khớp nhầm sang lớp cha và bỏ qua hoàn toàn xử lý của lớp con chuyên biệt.
*   **Cơ chế thực tế**: Spring Security/Spring MVC tìm kiếm `@ExceptionHandler` dựa trên **thuật toán tiệm cận nhất (most specific match)**. Nó sẽ duyệt cây kế thừa của Exception ném ra và tìm kiếm handler khớp gần nhất với lớp Exception đó. Do đó, cho dù thứ tự dòng viết trong file thế nào, `ResourceNotFoundException` vẫn luôn được ưu tiên xử lý bởi phương thức khai báo đích danh nó trước khi trượt xuống `Exception.class`.
*   *Lưu ý khi có nhiều lớp ControllerAdvice*: Nếu hệ thống của bạn quá lớn và chia làm nhiều lớp `@ControllerAdvice` khác nhau, hãy sử dụng chú thích **`@Order`** (ví dụ: `@Order(Ordered.HIGHEST_PRECEDENCE)`) để định nghĩa rõ ràng độ ưu tiên chạy của từng bộ xử lý.

### 2. Phân biệt `@ControllerAdvice` vs `@RestControllerAdvice`
*   **`@ControllerAdvice`**: Được dùng trong các ứng dụng Spring MVC truyền thống có kết xuất giao diện (Server-side rendering - JSP, Thymeleaf). Phương thức xử lý mặc định trả về một chuỗi đại diện cho tên của `View` (giao diện HTML) hiển thị trang lỗi. Nếu muốn trả về JSON, bạn phải chú thích thêm `@ResponseBody` trước mỗi phương thức.
*   **`@RestControllerAdvice`**: Là sự kết hợp của `@ControllerAdvice` và `@ResponseBody`. Thích hợp hoàn hảo cho việc xây dựng RESTful API. Mọi phản hồi trả về từ các `@ExceptionHandler` tự động được serialize thành định dạng JSON chuẩn.
