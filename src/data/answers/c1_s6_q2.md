# Dependency Injection là gì? Phân tích 3 loại DI và Nguyên tắc Hollywood

## ⚡ Tóm tắt ngắn (30s)
`Dependency Injection (DI)` là một Design Pattern cụ thể dùng để hiện thực hóa nguyên lý **Inversion of Control (IoC)**.
* **Bản chất**: Thay vì một đối tượng (Client) tự chịu trách nhiệm tìm kiếm hoặc khởi tạo các đối tượng phụ thuộc (Dependencies), các dependencies này sẽ được **tiêm (inject)** vào client từ bên ngoài thông qua một bên thứ ba (Spring IoC Container).
* **Nguyên tắc Hollywood ("Don't call us, we'll call you")**: Đừng tự gọi đi tìm phụ thuộc, IoC Container sẽ tự tìm và chủ động tiêm phụ thuộc đó vào class của bạn khi cần thiết.
* **Các kiểu DI**: Có 3 cách tiêm dependency chính trong Spring: **Constructor Injection**, **Setter Injection**, và **Field Injection**. Trong đó, **Constructor Injection** được coi là Best Practice tiêu chuẩn ngành.

## 🔍 Chi tiết bản chất thực chiến

### 1. Triết lý Hollywood: "Don't call us, we'll call you"
Trong lập trình truyền thống, nếu `UserService` muốn lưu dữ liệu, nó sẽ chủ động gọi `new UserRepository()` (chủ động liên hệ).
Dưới sự vận hành của DI theo nguyên tắc Hollywood: `UserService` chỉ cần khai báo một vị trí trống dành cho `UserRepository`. Khi khởi chạy, Spring Container (trong vai trò nhà tuyển dụng Hollywood) sẽ tự tìm kiếm `UserRepository` bean trong vùng nhớ của nó và lắp ráp vào `UserService` (Spring chủ động gọi/tiêm vào).

### 2. Phân tích 3 loại Dependency Injection trong Spring

#### A. Constructor Injection (Tiêm qua Constructor)
Các dependencies được truyền trực tiếp qua constructor của class.
*   **Best Practice**: Được Spring khuyến nghị tối đa từ phiên bản 4.x trở đi.
*   **Đặc điểm nổi bật**: Đảm bảo các dependency là bắt buộc (`non-null`) và hỗ trợ tính bất biến (`immutable` với từ khóa `final`).

#### B. Setter Injection (Tiêm qua Setter Method)
Dependencies được tiêm thông qua các public setter methods có đánh dấu `@Autowired`.
*   **Ứng dụng**: Phù hợp cho các phụ thuộc tùy chọn (optional dependencies) hoặc các giá trị cấu hình có thể thay đổi/tiêm lại tại runtime.

#### C. Field Injection (Tiêm trực tiếp vào Field)
Dependencies được tiêm trực tiếp vào thuộc tính của class thông qua reflection bằng cách đặt `@Autowired` ngay trên field (thậm chí là `private` field).
*   **Cảnh báo**: Đây là một **Anti-pattern** nguy hiểm, dù code trông rất gọn gàng nhưng mang lại nhiều rủi ro nghiêm trọng về bảo trì và kiểm thử.

## 💻 Code thực chiến: BAD vs GOOD

### ❌ BAD: Lạm dụng Field Injection
```java
package com.example.service;

import com.example.repository.UserRepository;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

@Service
public class UserServiceBad {

    @Autowired // Field Injection - Nhìn rất ngắn gọn nhưng ẩn chứa hiểm họa!
    private UserRepository userRepository;

    public void processUser(Long id) {
        // Nếu chạy Unit Test mà không load toàn bộ Spring Context (@SpringBootTest),
        // userRepository sẽ bị NullPointerException vì không có cơ chế tiêm thủ công.
        userRepository.deleteById(id);
    }
}
```

###  GOOD: Sử dụng Constructor Injection (Không cần đánh dấu @Autowired từ Spring 4.3+)
```java
package com.example.service;

import com.example.repository.UserRepository;
import org.springframework.stereotype.Service;
import java.util.Objects;

@Service
public class UserServiceGood {

    // 1. Khai báo final đảm bảo immutability (an toàn đa luồng)
    private final UserRepository userRepository;

    // 2. Tiêm qua constructor. Nếu class chỉ có một constructor, 
    // Spring tự hiểu để DI mà không cần annotation @Autowired.
    public UserServiceGood(UserRepository userRepository) {
        // Đảm bảo fail-fast nếu dependency bị truyền null ngoài ý muốn
        this.userRepository = Objects.requireNonNull(userRepository, "UserRepository must not be null");
    }

    public void processUser(Long id) {
        userRepository.deleteById(id);
    }
}
```

## 📊 Trade-off: So sánh 3 kỹ thuật Dependency Injection

| Tiêu chí | Constructor Injection (Best) | Setter Injection | Field Injection (Bad) |
| :--- | :--- | :--- | :--- |
| **Tính bất biến (Immutability)** |  Có (Cho phép dùng `final` field). | ❌ Không. | ❌ Không. |
| **An toàn trước Null (NPE Safe)** |  Tuyệt đối (JVM không cho tạo object nếu thiếu dependency). | ❌ Không (Đối tượng có thể ở trạng thái nửa chừng chưa cấu hình xong). | ❌ Không (Dễ dính NPE trong Unit Test). |
| **Độ dễ viết Unit Test** |  Rất dễ (Truyền thủ công qua constructor mà không cần Spring). | Trung bình (Cần gọi các hàm setter). |  Rất khó (Phải dùng Reflection hoặc `@SpringBootTest` nặng nề). |
| **Phát hiện Circular Dependency** |  Tức thời khi startup ứng dụng. | ❌ Trễ (Chỉ phát hiện khi method được gọi). | ❌ Trễ. |
| **Cảnh báo vi phạm SRP** |  Có (Constructor quá nhiều params sẽ báo động code mùi). | ❌ Không. |  Không (Thêm 20 `@Autowired` fields code vẫn trông "gọn"). |

## ⚠️ Common Gotchas & Questions follow-up

* **Cạm bẫy che giấu thiết kế tồi (SRP Violation with Field Injection)**:
  Khi sử dụng Field Injection, lập trình viên rất dễ vi phạm nguyên tắc **Single Responsibility Principle (SRP)** bằng cách tiêm vô số dependencies vào một class. Vì mỗi dòng chỉ tốn một annotation `@Autowired`, code nhìn bề ngoài vẫn sạch sẽ.
  * *Khắc phục:* Chuyển sang Constructor Injection. Một constructor có hơn 5-7 tham số sẽ khiến IDE cảnh báo hoặc lập trình viên ngửi thấy "code mùi" ngay lập tức, từ đó thúc đẩy việc refactor tách nhỏ class.
* **Câu hỏi đào sâu từ interviewer**: *Làm thế nào để Spring biết nên chọn Bean nào nếu có tới 2 Class cùng implement một Interface và ta tiến hành DI interface đó?*
  * *(Trả lời: Spring sẽ ném ra ngoại lệ `NoUniqueBeanDefinitionException` vì mập mờ định nghĩa. Để giải quyết, ta có 3 cách:
    1. Dùng `@Primary` trên Class muốn làm mặc định.
    2. Dùng `@Qualifier("beanName")` tại vị trí tiêm để chỉ định chính xác Bean.
    3. Đặt tên biến trùng khớp với tên Class cần tiêm (ví dụ: `private final PaymentService momoPaymentService` sẽ khớp với bean tên `momoPaymentService` nhờ cơ chế By-Name fallback của Spring).*
