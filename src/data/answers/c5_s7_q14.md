# LLM Trả lời Chậm làm Request giữ Thread quá lâu

## ⚡ Tóm tắt ngắn (30s)
* **Symptom**: LLM takes 30s+ to respond → backend thread blocked → throughput drop → cascading failures (queue full, ALB timeout).
* **Causes**:
  1. **Blocking I/O** (RestTemplate / sync HTTP client).
  2. Tomcat thread pool exhausted.
  3. No timeout / very long timeout.
  4. No bulkhead.
* **Fix**:
  1. Switch to reactive (WebFlux / WebClient).
  2. Set strict timeout.
  3. Bulkhead Resilience4j.
  4. Streaming SSE.

---

## 💻 Reactive (WebFlux)

```java
@RestController
public class ChatController {
    
    @PostMapping(value = "/chat", produces = TEXT_EVENT_STREAM_VALUE)
    public Flux<String> chat(@RequestBody ChatReq req) {
        return webClient.post()
            .uri("/openai/...")
            .bodyValue(req)
            .retrieve()
            .bodyToFlux(String.class)
            .timeout(Duration.ofSeconds(60))
            // Non-blocking: thread released while waiting
            .doOnCancel(() -> log.info("Cancelled"));
    }
}
```

## 💻 Bulkhead

```yaml
resilience4j:
  bulkhead:
    instances:
      llm:
        maxConcurrentCalls: 50  # cap concurrent
        maxWaitDuration: 1s
```

```java
@Bulkhead(name = "llm")
public Mono<String> callLlm(...) { ... }
```

## 📊 Comparison

| Pattern | Thread per request | Throughput | Scalability |
| :--- | :---: | :---: | :---: |
| Sync RestTemplate | 1 per LLM call | Low | Limited |
| Async CompletableFuture | 0 (event loop) | High | Good |
| Reactive WebFlux | 0 | High | Best |

## ⚠️ Interviewer

**"Tomcat thread exhausted serving LLM. Migration to WebFlux?"**
1. Identify hotspot: SSE chat endpoints.
2. Wrap with @Async if minimal change OK.
3. Or migrate full to WebFlux: requires testing entire stack.
4. Hybrid: critical endpoints reactive, others sync.
5. Bulkhead and timeout while migrating.
