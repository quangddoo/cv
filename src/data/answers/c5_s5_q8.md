# Có nên gửi PII/User Data lên LLM Provider không

## ⚡ Tóm tắt ngắn (30s)
* **Tùy provider + tùy data + tùy compliance**. Không phải absolute yes/no.
* **3 trường hợp PHẢI cẩn thận**:
  1. **Healthcare (HIPAA)**: PHI cần BAA với provider.
  2. **Financial (PCI-DSS)**: credit card data — never to standard LLM.
  3. **EU GDPR**: data residency restrictions.
* **Provider tier**:
  1. **Best**: managed cloud (AWS Bedrock, Azure OpenAI) — DPA, no training, regional, audit trail.
  2. **OK**: OpenAI/Anthropic enterprise tier với DPA + zero data retention.
  3. **Risky**: free/consumer tier — data may be used for training.
* **Strategies giảm exposure**:
  1. Redact PII trước khi gửi.
  2. Tokenize/pseudonymize.
  3. Self-host model cho data cực sensitive.
  4. Differential privacy / aggregation.
* **Thảm họa thực chiến**: Healthcare app gửi PHI (patient names, diagnosis) tới OpenAI consumer API. HIPAA fine + reputation. Senior fix: switch sang Bedrock với BAA + redact identifiers.

## 💻 Pseudonymization pattern

```java
@Service
public class DataPseudonymizer {
    
    private final Map<String, String> tokenMap = new ConcurrentHashMap<>();
    
    public String pseudonymize(String text) {
        // Replace email with TOKEN_EMAIL_1, etc.
        text = text.replaceAll("\\S+@\\S+", m -> {
            String token = "TOKEN_EMAIL_" + tokenMap.size();
            tokenMap.put(token, m);
            return token;
        });
        // Similar for phone, SSN, etc.
        return text;
    }
    
    public String reversePseudonymize(String response) {
        for (var entry : tokenMap.entrySet()) {
            response = response.replace(entry.getKey(), entry.getValue());
        }
        return response;
    }
}

// Usage
String pseudoUser = pseudonymizer.pseudonymize(userMessage);
String pseudoResp = llm.chat(pseudoUser);
String realResp = pseudonymizer.reversePseudonymize(pseudoResp);
```

## 📊 Provider DPA checklist

When evaluating provider:
- [ ] DPA / BAA available?
- [ ] Data used for training? (NO is best)
- [ ] Data retention policy (zero retention possible?).
- [ ] Regional data residency (EU, US specific).
- [ ] SOC 2 / ISO 27001 cert.
- [ ] Sub-processor list (transparent).
- [ ] Breach notification SLA.
- [ ] Right to audit.
- [ ] Encryption in transit + at rest.

## ⚠️ Gotchas + Interviewer

1. **DPA gap**: standard tier has no DPA; need enterprise.
2. **Sub-processors**: provider may use sub-contractors → also need DPA chain.
3. **Logs by provider**: provider keeps logs for X days — may have your data.

**Interviewer: "Customer asks 'where exactly does my prompt go?' Trace?"**
1. Browser → ALB.
2. ALB → Backend (us-east-1).
3. Backend → LLM via VPC endpoint (private link).
4. LLM provider (us-east-1).
5. Response back same path.
6. Audit log → S3 (encrypted, same region).
7. NO cross-region. NO training.
8. Document this trace; share with customer if asked.
