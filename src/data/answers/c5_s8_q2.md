# Khi nào Chọn Fine-tuning thay vì RAG

## ⚡ Tóm tắt ngắn (30s)
* Refer c5_s1_q13.
* **Chọn Fine-tune khi**:
  1. **Custom format/style/tone**: legal jargon, brand voice.
  2. **Structured output strict**: extract 50 fields, always JSON.
  3. **Low-latency requirement**: prompt ngắn (no RAG context).
  4. **High volume narrow task**: distill big model to small model.
  5. **Có dataset > 1000 quality examples**.
  6. **Cost optimization at scale**: 100M req/month, prompt overhead matters.

---

## 🔍 Patterns

### 1. Format/tone consistency
LLM normally responds with format variance. FT enforces: always JSON, always one style.

### 2. Distillation
Use GPT-4o expensive to generate 10k examples → FT gpt-4o-mini → run cheap at scale.

### 3. Domain language
Legal "force majeure", medical jargon, internal slang.

---

## 📊 ROI calculation

Example: 10M req/month.
* **Without FT**: gpt-4o $2.5/1M input × 5k tokens/req × 10M = $125k/month.
* **With FT** (using gpt-4o-mini fine-tuned): $0.30/1M × shorter prompt 1k × 10M = $3k/month.

Savings: $122k/month. Worth FT cost ($1k one-time + $0.001/M token usage premium).

## ⚠️ Interviewer

**"FT vs prompt engineering, when?"**
1. Try prompt eng first.
2. If quality plateau + have data → FT.
3. FT for FORM, RAG for FACT.
4. Can combine: FT + RAG.
