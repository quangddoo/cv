# Kiểm tra tính hợp lệ của các dấu ngoặc (Validate Parentheses)

## ⚡ Tóm tắt ngắn (30s)
* **Bài toán**: Cho một chuỗi ký tự chỉ chứa các ký hiệu đóng mở ngoặc gồm `(`, `)`, `[`, `]`, `{`, `}`. Kiểm tra xem chuỗi ngoặc đó có hợp lệ hay không. Một chuỗi hợp lệ là khi tất cả các dấu ngoặc mở được đóng đúng thứ tự bởi dấu ngoặc đóng tương ứng.
* **Giải pháp cốt lõi**:
  1. **Sử dụng Ngăn xếp (Stack)**: Cơ chế LIFO (Last-In-First-Out) hoàn hảo để giải quyết bài toán này.
  2. **Thuật toán**: Duyệt qua từng ký tự trong chuỗi:
     * Nếu gặp ngoặc mở (`(`, `[`, `{`), ta đẩy dấu ngoặc đóng tương ứng (`)`, `]`, `}`) vào Stack.
     * Nếu gặp ngoặc đóng, ta lấy phần tử ở đỉnh Stack ra (pop) và so sánh. Nếu không khớp hoặc Stack rỗng, trả về `false`.
     * Khi duyệt hết chuỗi, Stack bắt buộc phải **rỗng** thì chuỗi mới hợp lệ.
* **Độ phức tạp**: Thời gian $O(N)$, không gian $O(N)$ với $N$ là độ dài chuỗi ký tự.

---

## 🔍 Phân tích yêu cầu (Requirements)

### 1. Functional Requirements (Yêu cầu chức năng)
* Nhận đầu vào là một chuỗi ký tự có độ dài bất kỳ (có thể chứa ký tự trống hoặc ký tự khác nếu đề bài mở rộng).
* Trả về kết quả Boolean (`true` nếu chuỗi hợp lệ, ngược lại `false`).
* Xử lý chính xác các cặp ngoặc đan xen nhau theo cấp, ví dụ: `{[()]}` là hợp lệ, `([)]` là không hợp lệ.

### 2. Non-Functional Requirements (Yêu cầu phi chức năng)
* **Tối ưu hóa hiệu năng (Performance Optimization)**: Với các chuỗi cực lớn (hàng triệu ký tự), giải pháp phải hạn chế tối đa việc tạo ra các đối tượng tạm thời trên bộ nhớ Heap (tránh Boxing/Unboxing đối tượng `Character` của Java).
* **Độ trễ thấp**: Thời gian chạy thực tế phải đạt tối ưu cao nhất bằng cách duyệt mảng thô (primitive array).

### Mô phỏng luồng chạy của Stack với chuỗi hợp lệ "{( )}"

```
 1. Duyệt '{' (Ngoặc mở)          2. Duyệt '(' (Ngoặc mở)          3. Duyệt ')' (Ngoặc đóng)
    Push ngoặc đóng '}' vào Stack     Push ngoặc đóng ')' vào Stack     Pop đỉnh Stack so sánh với ')'
                                                                       ===> Khớp!
    ┌───────────┐                     ┌───────────┐                    ┌───────────┐
    │           │                     │     )     │ ◄── Đỉnh Stack     │           │
    │     }     │ ◄── Đỉnh Stack      │     }     │                    │     }     │ ◄── Đỉnh Stack
    └───────────┘                     └───────────┘                    └───────────┘

 4. Duyệt '}' (Ngoặc đóng)         5. Kết thúc chuỗi
    Pop đỉnh Stack so sánh với '}'     Stack rỗng hoàn toàn!
    ===> Khớp!                         ===> KẾT LUẬN: HỢP LỆ (TRUE)
    ┌───────────┐
    │           │
    │           │
    └───────────┘
```

## 💻 Code Example: Hiện thực hóa thuật toán bằng Java

Dưới đây là phiên bản hiện thực hóa tối ưu hóa cao độ bằng Java. Thay vì sử dụng lớp `Stack<Character>` của thư viện sẵn có (vốn bị chậm do đồng bộ hóa synchronized lỗi thời và tạo đối tượng Heap), chúng ta tự triển khai một Stack mảng thô (`char[]`) siêu nhanh:

```java
public class ParenthesesValidator {

    /**
     * Phương thức kiểm tra tính hợp lệ sử dụng mảng thô tối ưu hóa tốc độ và RAM
     */
    public boolean isValid(String s) {
        if (s == null) {
            return false;
        }
        
        int length = s.length();
        // Một chuỗi có độ dài lẻ chắc chắn không thể ghép cặp hợp lệ (Gotcha 2)
        if (length % 2 != 0) {
            return false;
        }

        // Tự tạo một Stack bằng mảng char thô để đạt hiệu năng đỉnh cao
        // Dung lượng Stack tối đa chỉ cần bằng một nửa độ dài chuỗi
        char[] stack = new char[length];
        int head = 0; // Con trỏ quản lý đỉnh Stack

        for (int i = 0; i < length; i++) {
            char c = s.charAt(i);

            // Khi gặp ngoặc mở, ta push ngoặc đóng tương ứng vào Stack
            if (c == '(') {
                stack[head++] = ')';
            } else if (c == '[') {
                stack[head++] = ']';
            } else if (c == '{') {
                stack[head++] = '}';
            } else {
                // Khi gặp ngoặc đóng:
                // Nếu Stack đang rỗng (head == 0) hoặc ký tự hiện tại không khớp với đỉnh Stack
                if (head == 0 || stack[--head] != c) {
                    return false;
                }
            }
        }

        // Nếu head == 0 tức là toàn bộ dấu ngoặc mở đã được ghép đôi đóng hoàn toàn
        return head == 0;
    }

    // --- Hàm Demo chạy thử ---
    public static void main(String[] args) {
        ParenthesesValidator validator = new ParenthesesValidator();

        String case1 = "()[]{}";
        String case2 = "{[()]}";
        String case3 = "([)]";
        String case4 = "(";

        System.out.printf("Chuỗi: %-8s | Hợp lệ: %b\n", case1, validator.isValid(case1)); // true
        System.out.printf("Chuỗi: %-8s | Hợp lệ: %b\n", case2, validator.isValid(case2)); // true
        System.out.printf("Chuỗi: %-8s | Hợp lệ: %b\n", case3, validator.isValid(case3)); // false
        System.out.printf("Chuỗi: %-8s | Hợp lệ: %b\n", case4, validator.isValid(case4)); // false
    }
}
```

## 📊 Phân tích độ phức tạp & Trade-offs

### So sánh các giải pháp giải quyết bài toán

| Phương pháp | Sử dụng `String.replace()` đệ quy | Sử dụng `Stack<Character>` chuẩn | Sử dụng Mảng thô `char[]` (Tối ưu) |
| :--- | :--- | :--- | :--- |
| **Cách làm** | Vòng lặp `while (s.contains("()") || s.contains("[]") ...)` rồi thay thế bằng chuỗi rỗng. | Sử dụng Java Collection `Stack` hoặc `Deque` chuẩn để đẩy các đối tượng. | Tự quản lý mảng ký tự thô và con trỏ chỉ số đỉnh stack. |
| **Độ phức tạp thời gian** | **Kém**: $O(N^2)$ vì mỗi lần tìm kiếm và thay thế chuỗi phải quét toàn bộ lại từ đầu. | **Tốt**: $O(N)$ duyệt qua chuỗi đúng 1 lần. | **Tuyệt vời**: $O(N)$ duyệt 1 lần và thao tác mảng trực tiếp có hệ số thực thi (constant factor) siêu nhỏ. |
| **Độ phức tạp bộ nhớ** | **Kém**: Tạo ra vô số đối tượng String trung gian trên Heap, kích thích Garbage Collector hoạt động liên tục. | **Vừa phải**: $O(N)$ nhưng tốn tài nguyên do hiện tượng **Auto-boxing** biến kiểu dữ liệu nguyên thủy `char` thành Đối tượng `Character`. | **Tối ưu nhất**: $O(N)$ chỉ cấp phát đúng một mảng ký tự nguyên thủy một lần duy nhất trên Stack/Heap nhẹ. |

## ⚠️ Common Gotchas (Câu hỏi đào sâu từ interviewer)

### 1. Nếu đề bài thay đổi: Chuỗi CHỈ CHỨA DUY NHẤT một loại dấu ngoặc mở rộng là `(` và `)`. Bạn có thể tối ưu không gian bộ nhớ (Space Complexity) xuống $O(1)$ được không?
* **Trả lời**: Hoàn toàn được! Đây là cơ hội ghi điểm cực lớn trước nhà tuyển dụng:
  * **Giải pháp $O(1)$ bộ nhớ**: Thay vì cần cả một ngăn xếp Stack để ghi nhớ vị trí, ta chỉ cần sử dụng duy nhất một biến đếm kiểu số nguyên `int balance = 0`:
    * Duyệt chuỗi từ trái qua phải. Khi gặp `(`, ta tăng `balance++`. Khi gặp `)`, ta giảm `balance--`.
    * Nếu tại bất kỳ thời điểm nào trong lúc duyệt mà `balance < 0` (nghĩa là có dấu ngoặc đóng xuất hiện trước ngoặc mở), ta trả về `false` ngay lập tức.
    * Khi kết thúc chuỗi, nếu `balance == 0`, trả về `true`, ngược lại `false`.
  * **Tại sao không áp dụng được cho nhiều loại ngoặc**: Vì biến đếm số lượng không ghi nhớ được **thứ tự xuất hiện** đan xen của các loại dấu ngoặc khác nhau (ví dụ: `([)]` có số lượng mở đóng bằng nhau nhưng sai thứ tự). Do đó bắt buộc phải dùng Stack khi có từ 2 loại ngoặc trở lên.

### 2. Những trường hợp biên (Edge Cases) nào cần đặc biệt lưu ý để tránh lỗi logic?
* **Trả lời**:
  * **Chuỗi có độ dài lẻ**: Luôn kiểm tra `s.length() % 2 != 0` ở đầu hàm để trả về `false` ngay lập tức (tiết kiệm CPU). Một chuỗi lẻ chắc chắn không thể kết cặp cân xứng.
  * **Chuỗi toàn dấu ngoặc mở**: Ví dụ `((((`. Lúc này Stack sẽ liên tục được nạp đầy mà không bao giờ bị pop. Ta cần kiểm tra điều kiện cuối cùng `head == 0` (hoặc `stack.isEmpty()`) để đảm bảo không bỏ sót dấu ngoặc chưa đóng.
  * **Chuỗi bắt đầu bằng dấu ngoặc đóng**: Ví dụ `)[]`. Lúc này Stack đang trống rỗng nhưng ta lại gặp ngoặc đóng dẫn đến lệnh pop bị lỗi. Phải kiểm tra điều kiện rỗng `head == 0` trước khi pop để trả về `false` kịp thời.

### 3. Tại sao trong Java khuyên dùng `ArrayDeque` thay thế cho lớp `Stack` truyền thống khi cần cấu trúc Ngăn xếp?
* **Trả lời**: 
  * Lớp `java.util.Stack` được kế thừa từ lớp `Vector` cổ điển từ thời Java 1.0. Tất cả các phương thức của nó đều sử dụng từ khóa `synchronized` (khóa toàn cục luồng). Điều này gây suy giảm hiệu năng nghiêm trọng do luồng phải tranh chấp khóa kể cả khi chạy đơn luồng.
  * `ArrayDeque` không đồng bộ hóa luồng (non-synchronized), được thiết kế tối ưu trên mảng động tuần hoàn, mang lại tốc độ thực thi vượt trội khi làm cấu trúc Stack. Tuy nhiên để đạt tốc độ cao nhất trong các bài thi coding, tự viết mảng thô `char[]` vẫn là số một!
