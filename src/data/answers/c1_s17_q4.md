# Tìm K phần tử xuất hiện nhiều nhất (Top K Frequent Elements)

## ⚡ Tóm tắt ngắn (30s)
* **Bài toán**: Cho một mảng số nguyên `nums` và một số nguyên `k`, hãy tìm $K$ phần tử xuất hiện nhiều nhất trong mảng.
* **2 Cách tiếp cận tối ưu**:
  1. **Min-Heap (PriorityQueue)**:
     * Dùng HashMap để đếm tần suất xuất hiện của các số: $O(N)$.
     * Duy trì một Min-Heap có kích thước cố định bằng $K$. Duyệt qua các entry trong HashMap và thêm vào Heap. Nếu kích thước Heap vượt quá $K$, loại bỏ phần tử có tần suất nhỏ nhất ở đầu Heap (`poll`).
     * **Độ phức tạp**: Thời gian $O(N \log K)$, Không gian $O(N + K)$.
  2. **Bucket Sort (Sắp xếp theo thùng - Khuyên dùng)**:
     * Đếm tần suất bằng HashMap: $O(N)$.
     * Tạo một mảng các danh sách (buckets) có kích thước bằng $N + 1$, trong đó **chỉ số (index) của mảng chính là tần suất xuất hiện** và giá trị tại index đó là danh sách các số đạt tần suất này.
     * Duyệt mảng buckets ngược từ cuối về đầu (từ tần suất cao nhất xuống thấp nhất) để thu thập đủ $K$ phần tử.
     * **Độ phức tạp**: Thời gian **$O(N)$ (tuyến tính cực hạn)**, Không gian $O(N)$.

## 🔍 Phân tích yêu cầu (Requirements)

### 1. Functional Requirements (Yêu cầu chức năng)
* **Đầu vào**: Mảng số nguyên `nums` và số nguyên dương `k` ($1 \le k \le \text{số lượng phần tử duy nhất}$).
* **Đầu ra**: Mảng hoặc danh sách chứa $K$ phần tử xuất hiện nhiều nhất. Thứ tự của các phần tử trong kết quả trả về không quan trọng.
* **Điều kiện biên (Edge cases)**:
  * Mảng chỉ có 1 phần tử: $K$ chắc chắn bằng 1, trả về chính phần tử đó.
  * Tất cả các phần tử có tần suất bằng nhau: Trả về $K$ phần tử bất kỳ.

### 2. Non-Functional Requirements (Yêu cầu phi chức năng)
* **Tối ưu hóa thời gian**: Với bộ dữ liệu cực lớn, độ phức tạp $O(N)$ của Bucket Sort sẽ vượt trội hơn hẳn so với $O(N \log N)$ của việc sắp xếp thông thường.
* **Khả năng mở rộng (Scalability)**: Thảo luận phương án xử lý khi luồng dữ liệu là cực lớn (Big Data) không thể chứa vừa trong RAM của một máy.

## 💻 Code Example: Hai phương pháp trong Java

### Giải pháp 1: Sử dụng Bucket Sort (Tốc độ $O(N)$ tối ưu)

Đây là giải pháp tốt nhất về mặt lý thuyết thời gian, giúp bạn gây ấn tượng mạnh mẽ với nhà tuyển dụng nhờ việc loại bỏ hoàn toàn toán tử Logarithm ($\log$).

```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

public class TopKFrequentBucketSort {
    
    public int[] topKFrequent(int[] nums, int k) {
        // Bước 1: Đếm tần suất xuất hiện của từng số bằng HashMap
        Map<Integer, Integer> frequencyMap = new HashMap<>();
        for (int num : nums) {
            frequencyMap.put(num, frequencyMap.getOrDefault(num, 0) + 1);
        }

        // Bước 2: Tạo mảng các bucket. Kích thước tối đa của tần suất là nums.length
        // Mỗi phần tử trong mảng bucket là một List chứa các số có cùng tần suất
        List<Integer>[] bucket = new List[nums.length + 1];
        
        for (Map.Entry<Integer, Integer> entry : frequencyMap.entrySet()) {
            int num = entry.getKey();
            int frequency = entry.getValue();
            
            if (bucket[frequency] == null) {
                bucket[frequency] = new ArrayList<>();
            }
            bucket[frequency].add(num);
        }

        // Bước 3: Thu thập K phần tử xuất hiện nhiều nhất bằng cách duyệt ngược mảng bucket
        int[] result = new int[k];
        int resultIndex = 0;
        
        for (int pos = bucket.length - 1; pos >= 0 && resultIndex < k; pos--) {
            if (bucket[pos] != null) {
                for (int num : bucket[pos]) {
                    result[resultIndex++] = num;
                    if (resultIndex == k) {
                        return result; // Đã tìm đủ K phần tử
                    }
                }
            }
        }
        
        return result;
    }
}
```

### Giải pháp 2: Sử dụng Min-Heap (PriorityQueue - $O(N \log K)$)

Giải pháp này cực kỳ hữu ích khi tham số $K$ rất nhỏ so với kích thước $N$ của mảng đầu vào, giúp tiết kiệm bộ nhớ hơn so với Bucket Sort.

```java
import java.util.HashMap;
import java.util.Map;
import java.util.PriorityQueue;

public class TopKFrequentMinHeap {
    
    public int[] topKFrequent(int[] nums, int k) {
        // Bước 1: Đếm tần suất xuất hiện
        Map<Integer, Integer> frequencyMap = new HashMap<>();
        for (int num : nums) {
            frequencyMap.put(num, frequencyMap.getOrDefault(num, 0) + 1);
        }

        // Bước 2: Tạo Min-Heap sắp xếp theo tần suất tăng dần
        // Phần tử có tần suất nhỏ nhất luôn nằm ở đầu Queue (head)
        PriorityQueue<Integer> minHeap = new PriorityQueue<>(
            (a, b) -> Integer.compare(frequencyMap.get(a), frequencyMap.get(b))
        );

        // Bước 3: Duy trì Heap kích thước K
        for (int num : frequencyMap.keySet()) {
            minHeap.add(num);
            if (minHeap.size() > k) {
                minHeap.poll(); // Loại bỏ phần tử có tần suất thấp nhất hiện tại
            }
        }

        // Bước 4: Chuyển dữ liệu từ Heap ra mảng kết quả
        int[] result = new int[k];
        for (int i = 0; i < k; i++) {
            result[i] = minHeap.poll();
        }
        
        return result;
    }
}
```

## 📊 Phân tích độ phức tạp & Trade-offs

### So sánh chi tiết hai phương pháp

| Tiêu chí | Giải pháp Min-Heap | Giải pháp Bucket Sort |
| :--- | :--- | :--- |
| **Độ phức tạp thời gian** | $O(N \log K)$ - Rất nhanh nếu $K \ll N$. | **$O(N)$** - Tuyến tính hoàn hảo, không phụ thuộc vào giá trị của $K$. |
| **Độ phức tạp không gian**| $O(N + K)$ - Tiết kiệm bộ nhớ hơn khi $K$ nhỏ vì Heap chỉ lưu tối đa $K$ phần tử. | $O(N)$ - Tốn bộ nhớ hơn do phải khởi tạo mảng danh sách bucket kích thước $N + 1$. |
| **Tính ứng dụng thực tế** | Rất tốt cho hệ thống Streaming. Khi có số mới đến, ta có thể cập nhật trực tiếp vào Heap trong $O(\log K)$. | Chỉ áp dụng hiệu quả cho dữ liệu tĩnh. Nếu dữ liệu phân tán hoặc liên tục thay đổi, việc chia bucket sẽ bị hạn chế. |

## ⚠️ Common Gotchas (Câu hỏi đào sâu từ interviewer)

### 1. Nếu kích thước mảng $N$ cực lớn (hàng tỷ số) không thể chứa vừa trong bộ nhớ của một máy, bạn giải quyết thế nào?
* **Trả lời**: Đây là bài toán thiết kế hệ thống ở scale lớn (Big Data / Distributed System).
  * **Phương tiếp cận MapReduce / Phân tán**:
    * **Map Phase**: Chia nhỏ file dữ liệu khổng lồ thành nhiều chunk nằm trên các node khác nhau. Mỗi node đếm tần suất cục bộ (local frequency) của các số thuộc chunk đó.
    * **Reduce Phase**: Tổng hợp tần suất của từng số từ các node khác nhau để có tần suất toàn cục (global frequency).
    * **Tìm Top K**: Thay vì gửi toàn bộ dữ liệu về một master node (gây nghẽn mạng và tràn RAM), mỗi node worker tự tìm kiếm Top K phần tử nhiều nhất của riêng mình (dùng Min-Heap kích thước $K$). Sau đó, chỉ gửi $K$ phần tử này về node trung tâm. Node trung tâm chỉ cần gộp mảng kết quả nhỏ từ các worker và tìm ra Top K cuối cùng.
  * **Giải pháp xấp xỉ (Approximate Solution)**: Sử dụng cấu trúc dữ liệu **Count-Min Sketch** (một dạng Bloom Filter mở rộng) để ước lượng tần suất xuất hiện của các phần tử với mức tiêu thụ bộ nhớ cố định cực nhỏ, chấp nhận sai số cực thấp.

### 2. Làm thế nào để giải quyết trường hợp tần suất xuất hiện bằng nhau (Ties)?
* **Trả lời**: Mặc định, đề bài Leetcode cho phép trả về kết quả theo thứ tự bất kỳ. Tuy nhiên, trong phỏng vấn thực tế, người phỏng vấn thường yêu cầu thêm: *"Nếu tần suất bằng nhau, ưu tiên số có giá trị nhỏ hơn nằm trước"*.
  * Đối với **Min-Heap**, ta chỉ cần thay đổi bộ so sánh (Comparator):
    ```java
    PriorityQueue<Integer> minHeap = new PriorityQueue<>((a, b) -> {
        int freqA = frequencyMap.get(a);
        int freqB = frequencyMap.get(b);
        if (freqA == freqB) {
            return Integer.compare(b, a); // Tần suất bằng nhau, số lớn hơn đứng trước trong Min-Heap để khi poll sẽ bị loại trước
        }
        return Integer.compare(freqA, freqB);
    });
    ```
  * Đối với **Bucket Sort**, sau khi thu được danh sách các số trong cùng một bucket, ta có thể thực hiện sort phụ danh sách đó trước khi trích xuất phần tử.
