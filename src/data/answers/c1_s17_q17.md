# Chuỗi con dài nhất không chứa ký tự trùng lặp (Longest Substring Without Repeating Characters)

## ⚡ Tóm tắt ngắn (30s)
* **Bài toán**: Cho một chuỗi ký tự `s`. Tìm độ dài của chuỗi con (substring - các ký tự liên tiếp nhau) dài nhất mà không có bất kỳ ký tự nào bị lặp lại.
* **Giải pháp cốt lõi**:
  1. **Kỹ thuật Cửa sổ trượt (Sliding Window)**: Sử dụng hai con trỏ `left` và `right` để tạo nên một cửa sổ chứa chuỗi con không trùng lặp hiện tại.
  2. **Bảng chỉ mục truy cập trực tiếp (Direct Address Table)**: Thay vì dùng `HashMap` chậm chạp, ta dùng một mảng số nguyên `int[128]` (hoặc `int[256]` cho bảng mã ASCII mở rộng) để ghi nhớ chỉ mục (index) xuất hiện cuối cùng của mỗi ký tự.
  3. **Thuật toán**: Duyệt con trỏ `right` từ đầu đến cuối chuỗi. Khi gặp ký tự đã tồn tại trong cửa sổ hiện tại, ta nhảy con trỏ `left` trực tiếp đến vị trí ngay sau vị trí cũ của ký tự trùng lặp đó. Liên tục cập nhật độ dài lớn nhất: `maxLen = max(maxLen, right - left + 1)`.
* **Độ phức tạp**: Thời gian $O(N)$ duyệt chuỗi đúng 1 lần duy nhất, không gian $O(\min(N, M))$ với $M$ là kích thước tập ký tự ($M \le 128$ với ASCII tiêu chuẩn).

---

## 🔍 Phân tích yêu cầu (Requirements)

### 1. Functional Requirements (Yêu cầu chức năng)
* Nhận đầu vào là một chuỗi ký tự bất kỳ (có thể trống, chứa chữ cái, chữ số, ký tự đặc biệt hoặc khoảng trắng).
* Trả về một số nguyên duy nhất là độ dài của chuỗi con dài nhất không trùng ký tự.
* Phân biệt chữ hoa và chữ thường (ví dụ: 'A' và 'a' được coi là hai ký tự khác nhau).

### 2. Non-Functional Requirements (Yêu cầu phi chức năng)
* **Tối ưu tốc độ tối đa**: Tránh lặp vô ích. Hạn chế sử dụng các lớp bọc Collection phức tạp. Thao tác thô trực tiếp trên mảng ký tự (`char[]`) của chuỗi để loại bỏ chi phí gọi hàm `charAt()`.

## 🎨 Sơ đồ trực quan & Giải thuật Sliding Window

### Walkthrough minh họa cửa sổ trượt với chuỗi "abcabcbb"

```
 Bước 1: right = 0, char = 'a'        Bước 2: right = 1, char = 'b'        Bước 3: right = 2, char = 'c'
 Cửa sổ: [a]bcabcbb                   Cửa sổ: [ab]cabcbb                   Cửa sổ: [abc]abcbb
 left = 0, right = 0                  left = 0, right = 1                  left = 0, right = 2
 maxLen = 1                           maxLen = 2                           maxLen = 3

 Bước 4: right = 3, char = 'a'        Bước 5: right = 4, char = 'b'        Bước 6: right = 5, char = 'c'
 Trùng 'a'! Dịch left = cũ('a')+1     Trùng 'b'! Dịch left = cũ('b')+1     Trùng 'c'! Dịch left = cũ('c')+1
 Cửa sổ: a[bca]bcbb                   Cửa sổ: ab[cab]cbb                   Cửa sổ: abc[abc]bb
 left = 1, right = 3                  left = 2, right = 4                  left = 3, right = 5
 maxLen = 3                           maxLen = 3                           maxLen = 3

 Bước 7: right = 6, char = 'b'        Bước 8: right = 7, char = 'b'
 Trùng 'b'! Dịch left = cũ('b')+1     Trùng 'b'! Dịch left = cũ('b')+1
 Cửa sổ: abcab[cb]b                   Cửa sổ: abcabc[b]b
 left = 5, right = 6                  left = 7, right = 7
 maxLen = 3                           maxLen = 3
```
> [!TIP]
> **Điểm đột phá**: Khi phát hiện ký tự trùng lặp, thay vì dịch con trỏ `left` từng bước một cách chậm chạp (như kiểu dùng Set), ta **nhảy vọt** `left` đến vị trí mới tối ưu nhất nhờ thông tin vị trí lưu trữ sẵn trong mảng chỉ mục!

## 💻 Code Example: Hiện thực hóa thuật toán bằng Java

Dưới đây là phiên bản hiện thực hóa tối ưu hóa hiệu năng cao nhất bằng Java, sử dụng mảng nguyên thủy `int[]` làm bảng tra cứu chỉ mục trực tiếp của bảng mã ASCII:

```java
public class LongestSubstring {

    public int lengthOfLongestSubstring(String s) {
        if (s == null || s.isEmpty()) {
            return 0;
        }

        // Chuyển String sang mảng char thô để tránh overhead của hàm charAt() (Gotcha 2)
        char[] chars = s.toCharArray();
        int n = chars.length;

        // Mảng ghi nhớ chỉ mục xuất hiện cuối cùng + 1 của ký tự trong chuỗi.
        // Khởi tạo mặc định toàn bộ bằng 0 (chưa xuất hiện).
        // Sử dụng kích thước 128 đại diện đủ cho bảng mã ASCII tiêu chuẩn.
        int[] lastSeenIndex = new int[128];
        
        int maxLength = 0;
        int left = 0; // Con trỏ bên trái của cửa sổ trượt

        for (int right = 0; right < n; right++) {
            char currentChar = chars[right];

            // Nếu ký tự hiện tại đã từng xuất hiện:
            // left nhảy trực tiếp tới vị trí lớn nhất giữa: vị trí hiện tại của left 
            // và vị trí ngay sau chỉ mục cũ của currentChar.
            left = Math.max(left, lastSeenIndex[currentChar]);

            // Cập nhật độ dài chuỗi con dài nhất
            maxLength = Math.max(maxLength, right - left + 1);

            // Ghi nhận chỉ mục xuất hiện cuối cùng của ký tự hiện tại (sử dụng index + 1)
            // Việc cộng 1 giúp ta phân biệt được vị trí 0 thực tế và vị trí mặc định 0 chưa xuất hiện
            lastSeenIndex[currentChar] = right + 1;
        }

        return maxLength;
    }

    // --- Hàm Demo chạy thử ---
    public static void main(String[] args) {
        LongestSubstring solver = new LongestSubstring();

        String s1 = "abcabcbb";
        String s2 = "bbbbb";
        String s3 = "pwwkew";
        String s4 = " ";

        System.out.printf("Chuỗi: %-10s | Độ dài lớn nhất: %d\n", "\"" + s1 + "\"", solver.lengthOfLongestSubstring(s1)); // 3 ("abc")
        System.out.printf("Chuỗi: %-10s | Độ dài lớn nhất: %d\n", "\"" + s2 + "\"", solver.lengthOfLongestSubstring(s2)); // 1 ("b")
        System.out.printf("Chuỗi: %-10s | Độ dài lớn nhất: %d\n", "\"" + s3 + "\"", solver.lengthOfLongestSubstring(s3)); // 3 ("wke")
        System.out.printf("Chuỗi: %-10s | Độ dài lớn nhất: %d\n", "\"" + s4 + "\"", solver.lengthOfLongestSubstring(s4)); // 1 (" ")
    }
}
```

## 📊 Phân tích độ phức tạp & Trade-offs

### So sánh các giải pháp giải quyết bài toán

| Tiêu chí | Giải pháp Brute Force (Vét cạn) | Sliding Window với `HashSet` | Sliding Window với `HashMap` | Sliding Window với Mảng `int[]` (Tối ưu) |
| :--- | :--- | :--- | :--- | :--- |
| **Cách làm** | Duyệt qua mọi cặp vị trí đầu cuối, kiểm tra xem chuỗi con đó có chứa trùng lặp không. | Dịch con trỏ `right`. Nếu trùng, dịch con trỏ `left` từng bước một và xóa ký tự khỏi `HashSet`. | Dùng Map lưu vị trí xuất hiện cuối cùng. Nhảy vọt con trỏ `left` bằng cách gọi hàm `map.get()`. | Dùng mảng nguyên thủy `int[]` thay thế Map để tra cứu chỉ mục tức thời. |
| **Thời gian chạy (Time Complexity)** | **Cực kém**: $O(N^3)$. | **Tốt**: $O(N)$ nhưng thực tế chậm do `left` phải dịch chuyển tịnh tiến từng bước và thao tác Hash đắt đỏ. | **Rất tốt**: $O(N)$ nhảy vọt `left` nhanh chóng. | **Tuyệt vời**: $O(N)$ nhanh nhất nhờ loại bỏ hoàn toàn chi phí tính toán mã Hash của đối tượng. |
| **Không gian bộ nhớ (Space)** | $O(\min(N, M))$ để lưu tập kiểm tra trùng lặp. | $O(\min(N, M))$ bộ nhớ lưu đối tượng Set trên Heap. | $O(\min(N, M))$ bộ nhớ lưu đối tượng Map trên Heap. | **Tối ưu nhất**: $O(M)$ bộ nhớ tĩnh cực nhỏ (cố định mảng 128 số nguyên). |

## ⚠️ Common Gotchas (Câu hỏi đào sâu từ interviewer)

### 1. Tại sao dòng lệnh `left = Math.max(left, lastSeenIndex[currentChar])` lại bắt buộc phải sử dụng hàm `Math.max` mà không gán thẳng `left = lastSeenIndex[currentChar]`?
* **Trả lời**: Đây là một chiếc bẫy logic cực kỳ tinh vi mà nhiều ứng viên hay mắc phải:
  * **Hiện tượng**: Giả sử ta duyệt chuỗi `"abba"`.
    * Duyệt đến ký tự `'b'` thứ hai ở index 2. Ta thấy `'b'` đã tồn tại ở index 1, dịch `left` lên index 2. Cửa sổ hiện tại là `"b"`.
    * Tiếp tục duyệt đến ký tự `'a'` thứ hai ở index 3. Lúc này, mảng `lastSeenIndex` của `'a'` đang ghi nhớ vị trí xuất hiện đầu tiên của nó ở index 0 (tức giá trị lưu là index+1 = 1).
    * Nếu ta **gán thẳng** `left = lastSeenIndex['a']` (tức là `left = 1`), con trỏ `left` sẽ bị **nhảy giật lùi** về vị trí index 1 (vốn nằm ngoài cửa sổ an toàn hiện tại đang ở index 2). Việc này làm cho cửa sổ trượt chứa cả ký tự `'b'` bị lặp lại ở index 1 và 2, dẫn đến kết quả sai hoàn toàn!
  * **Kết luận**: Việc dùng `Math.max` đảm bảo con trỏ `left` **chỉ được phép đi tiến lên phía trước**, không bao giờ bị nhảy giật lùi về phía sau các vị trí băm cũ nằm ngoài cửa sổ.

### 2. Nếu chuỗi đầu vào chứa các ký tự Unicode phức tạp (ví dụ: Tiếng Việt có dấu, ký tự Emoji) thay vì chỉ có ký tự ASCII tiêu chuẩn. Bạn giải quyết thế nào?
* **Trả lời**:
  * **Vấn đề**: Mảng chỉ mục trực tiếp `int[128]` hoặc `int[256]` chỉ đại diện đủ cho các ký tự thuộc bảng mã ASCII tiêu chuẩn (tiếng Anh không dấu). Nếu chuỗi đầu vào chứa Unicode (có thể lên tới hàng chục ngàn mã ký tự khác nhau), việc truy xuất `chars[right]` vượt quá 128 sẽ ném ra lỗi `ArrayIndexOutOfBoundsException`.
  * **Giải pháp khắc phục**:
    * Đối với môi trường thực tế doanh nghiệp: Ta chuyển đổi cấu trúc dữ liệu tra cứu từ mảng `int[]` sang **`HashMap<Character, Integer>`**. Dù hiệu năng có giảm đôi chút do Boxing đối tượng, nhưng nó hỗ trợ an toàn tuyệt đối 100% tất cả các loại ngôn ngữ Unicode trên thế giới.

### 3. Tại sao chuyển String thành `char[]` bằng hàm `s.toCharArray()` lại chạy nhanh hơn gọi trực tiếp `s.charAt(i)` trong vòng lặp?
* **Trả lời**:
  * Hàm `s.charAt(i)` của Java thực chất là một cuộc gọi phương thức (Method invocation). Bên trong hàm này phải thực hiện các bước kiểm tra biên an toàn (Range check: `if (index < 0 || index >= value.length) { throw new StringIndexOutOfBoundsException(); }`).
  * Việc lặp lại các bước kiểm tra biên này hàng triệu lần trong vòng lặp sẽ tiêu tốn CPU đáng kể.
  * Khi gọi `s.toCharArray()`, Java copy dữ liệu một lần duy nhất ra mảng ký tự thô. Việc duyệt mảng thô bằng chỉ số trực tiếp bỏ qua hoàn toàn các bước kiểm tra biên trung gian của hàm `charAt`, giúp JIT Compiler của JVM tối ưu hóa mã máy tốt hơn rất nhiều.
