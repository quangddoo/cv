# JWT Flow trong Spring Security: Bản chất stateless & Triển khai thực chiến

## ⚡ Tóm tắt ngắn (30s)
Luồng xác thực **JWT (JSON Web Token)** trong Spring Security là mô hình **Stateless (Không lưu trạng thái phía máy chủ)**. Máy chủ không lưu trữ session của người dùng, mọi thông tin danh tính và quyền hạn đều được đóng gói ngay bên trong token mã hóa gửi về phía Client.

**Quy trình 5 bước thực chiến**:
1.  **Đăng nhập**: Client gửi credentials (username/password) đến API `/login`.
2.  **Sinh Token**: Máy chủ xác thực thông tin, nếu đúng sẽ tạo JWT (chứa Subject, Roles, Expiration time, ký số bằng Private Secret Key) và trả về Client.
3.  **Lưu trữ**: Client lưu token trong `localStorage` hoặc bảo mật hơn là `HttpOnly Cookie`.
4.  **Gửi yêu cầu**: Với các request tiếp theo, Client đính kèm JWT vào header `Authorization: Bearer <token>`.
5.  **Xác thực tại Server**: Một Custom **`OncePerRequestFilter`** chặn request -> Phân tích (Parse) và xác thực tính hợp lệ của token -> Trích xuất danh tính và quyền hạn -> Nạp thông tin vào **`SecurityContextHolder`** -> Request đi tiếp đến Controller.

### 2. Sự cần thiết của `SessionCreationPolicy.STATELESS`
Để Spring Security hoạt động ở chế độ JWT thực thụ, chúng ta phải tắt cơ chế Session mặc định của Servlet:
```java
http.sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
```
*   **Bản chất**: Spring Security sẽ không tạo và không sử dụng `HttpSession`. Sau khi kết thúc mỗi request, **`SecurityContextHolder` sẽ bị xóa sạch (cleared)**. Điều này ép buộc mỗi request gửi tới đều phải đính kèm JWT để xác thực lại từ đầu. Hệ thống dễ dàng scale ngang (Horizontal Scaling) vì các service không cần chia sẻ bộ nhớ Session.

## 💻 Code thực chiến: BAD vs GOOD

### ❌ BAD: Viết Filter xác thực JWT sơ sài, thiếu xử lý lỗi và cứng mã khóa (Hardcoded Secret)
Bộ lọc JWT tự viết thiếu an toàn bảo mật, lộ khóa bí mật trong mã nguồn, và không bắt các lỗi token hết hạn (Expired), dẫn đến hệ thống bị sập luồng lọc hoặc quăng lỗi HTTP 500 vô nghĩa cho người dùng.

```java
package com.example.filter;

import org.springframework.web.filter.OncePerRequestFilter;
import javax.servlet.FilterChain;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.io.IOException;

// ❌ BAD: Code chắp vá, không xử lý lỗi phân tách, dùng thư viện cũ
public class JwtFilterBad extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)
            throws javax.servlet.ServletException, IOException {
        
        String authHeader = request.getHeader("Authorization");
        if (authHeader != null && authHeader.startsWith("Bearer ")) {
            String token = authHeader.substring(7);
            
            // ❌ Lỗi 1: Khóa bí mật cứng (Hardcoded) trực tiếp trong code
            String secret = "my-super-secret-key-that-is-too-short-and-unsafe"; 
            
            try {
                // Giả định parse token bằng thư viện cũ
                String username = "test_user"; // Mock parse
                
                // Nạp thẳng vào context mà không kiểm tra hạn dùng
                // ...
            } catch (Exception e) {
                // ❌ Lỗi 2: Nuốt exception hoặc để quăng lỗi 500 trực tiếp ra ngoài
                throw new RuntimeException("JWT Expired or Invalid");
            }
        }
        filterChain.doFilter(request, response);
    }
}
```

### ✅ GOOD: Triển khai JwtTokenProvider & JwtAuthenticationFilter chuẩn nghiệp vụ
Sử dụng thư viện bảo mật hiện đại (`io.jsonwebtoken` phiên bản mới), quản lý Secret Key an toàn bằng cấu hình bên ngoài, và bắt lỗi chi tiết để trả về mã lỗi 401 kèm thông điệp rõ ràng.

#### Bước 1: Bộ tiện ích quản lý Token (`JwtTokenProvider.java`)
```java
package com.example.security;

import io.jsonwebtoken.*;
import io.jsonwebtoken.security.Keys;
import jakarta.annotation.PostConstruct;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.stereotype.Component;
import java.nio.charset.StandardCharsets;
import java.security.Key;
import java.util.Date;

@Component
public class JwtTokenProvider {

    @Value("${app.jwt.secret}")
    private String jwtSecret; // ✅ Đọc từ file application.yml an toàn

    @Value("${app.jwt.expiration-ms}")
    private long jwtExpirationMs;

    private Key key;

    @PostConstruct
    public void init() {
        // ✅ Tạo khóa bảo mật chuẩn SHA-256 từ chuỗi cấu hình
        this.key = Keys.hmacShaKeyFor(jwtSecret.getBytes(StandardCharsets.UTF_8));
    }

    public String generateToken(String username) {
        Date now = new Date();
        Date expiryDate = new Date(now.getTime() + jwtExpirationMs);

        return Jwts.builder()
                .setSubject(username)
                .setIssuedAt(now)
                .setExpiration(expiryDate)
                .signWith(key, SignatureAlgorithm.HS256)
                .compact();
    }

    public String getUsernameFromJwt(String token) {
        Claims claims = Jwts.parserBuilder()
                .setSigningKey(key)
                .build()
                .parseClaimsJws(token)
                .getBody();
        return claims.getSubject();
    }

    public boolean validateToken(String authToken) {
        try {
            Jwts.parserBuilder().setSigningKey(key).build().parseClaimsJws(authToken);
            return true;
        } catch (JwtException | IllegalArgumentException ex) {
            // ✅ Bắt chi tiết lỗi (ExpiredJwtException, MalformedJwtException, SignatureException...)
            return false;
        }
    }
}
```

#### Bước 2: Bộ lọc xác thực request (`JwtAuthenticationFilter.java`)
```java
package com.example.security;

import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.web.authentication.WebAuthenticationDetailsSource;
import org.springframework.stereotype.Component;
import org.springframework.util.StringUtils;
import org.springframework.web.filter.OncePerRequestFilter;
import java.io.IOException;

@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    private final JwtTokenProvider tokenProvider;
    private final UserDetailsService userDetailsService;

    public JwtAuthenticationFilter(JwtTokenProvider tokenProvider, UserDetailsService userDetailsService) {
        this.tokenProvider = tokenProvider;
        this.userDetailsService = userDetailsService;
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)
            throws ServletException, IOException {
        try {
            String jwt = getJwtFromRequest(request);

            if (StringUtils.hasText(jwt) && tokenProvider.validateToken(jwt)) {
                String username = tokenProvider.getUsernameFromJwt(jwt);

                UserDetails userDetails = userDetailsService.loadUserByUsername(username);
                
                // ✅ Tạo đối tượng Authentication chuẩn của Spring Security
                UsernamePasswordAuthenticationToken authentication = new UsernamePasswordAuthenticationToken(
                        userDetails, null, userDetails.getAuthorities());
                
                authentication.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));

                // ✅ Thiết lập thông tin xác thực vào Security Context
                SecurityContextHolder.getContext().setAuthentication(authentication);
            }
        } catch (Exception ex) {
            // Không ném lỗi ra ngoài làm sập luồng lọc, để các Filter sau (ExceptionTranslationFilter) xử lý
            logger.error("Could not set user authentication in security context", ex);
        }

        filterChain.doFilter(request, response);
    }

    private String getJwtFromRequest(HttpServletRequest request) {
        String bearerToken = request.getHeader("Authorization");
        if (StringUtils.hasText(bearerToken) && bearerToken.startsWith("Bearer ")) {
            return bearerToken.substring(7);
        }
        return null;
    }
}
```

## ⚠️ Common Gotchas & Questions follow-up

### 1. Ngoại lệ trong Filter không thể bắt được bởi `@ControllerAdvice`!
Đây là lỗi cực kỳ kinh điển của các lập trình viên khi tích hợp JWT:
*   **Vấn đề**: Bạn viết một `@RestControllerAdvice` để bắt toàn bộ Exception của hệ thống và trả về JSON chuẩn. Nhưng khi JWT bị hết hạn (`ExpiredJwtException`), filter ném lỗi nhưng client nhận về mã HTML mặc định của Tomcat hoặc lỗi trắng trang (White Label Error Page) thay vì JSON format của bạn!
*   **Nguyên nhân**: `@ControllerAdvice` chỉ bắt được các ngoại lệ xảy ra bên trong **`DispatcherServlet`** (ở tầng Controller và Service). Trong khi đó, các Filter chạy **trước** khi request đi vào `DispatcherServlet`. Ngoại lệ ném ra ở Filter nằm ngoài tầm phủ sóng của ControllerAdvice.
*   **Giải pháp thực chiến**:
    1.  **Sử dụng `HandlerExceptionResolver`**: Inject Bean này vào Custom Filter và chuyển tiếp ngoại lệ cho nó xử lý để kích hoạt ngược lại ControllerAdvice:
        ```java
        @Autowired
        @Qualifier("handlerExceptionResolver")
        private HandlerExceptionResolver resolver;

        // Trong catch block của filter:
        resolver.resolveException(request, response, null, expiredException);
        ```
    2.  **Viết đè trực tiếp lên Response**: Bắt lỗi tại chỗ và ghi trực tiếp JSON thô vào HttpServletResponse với trạng thái `HttpServletResponse.SC_UNAUTHORIZED` (401).

### 2. Làm thế nào để vô hiệu hóa (Revoke) một JWT khi người dùng bấm Đăng xuất?
Vì JWT là stateless, máy chủ không lưu trạng thái nên không thể bảo token này "hết hiệu lực" trước thời gian hết hạn (`Expiration Time`) mặc định của nó.
*   **Giải pháp thực chiến tối ưu**:
    *   **Cơ chế Blacklist bằng Redis**: Khi người dùng nhấn Đăng xuất, lấy JWT hiện tại, tính toán thời gian sống còn lại (TTL) của token đó, và lưu token này vào Redis dưới dạng Blacklist key với TTL tương ứng. Khi `JwtAuthenticationFilter` chạy, nó sẽ kiểm tra token đó có nằm trong Redis Blacklist hay không. Nếu có -> Từ chối lập tức.
    *   **Mô hình Token đôi (Access Token & Refresh Token)**: Sử dụng Access Token có thời hạn cực ngắn (ví dụ: 15 phút) để giảm thiểu thiệt hại nếu bị lộ, kết hợp với Refresh Token lưu trong Database/Redis có hạn dài hơn (ví dụ: 7 ngày) để cấp lại Access Token mới mà người dùng không cần đăng nhập lại. Khi đăng xuất, chỉ cần xóa Refresh Token trong Database là đủ vô hiệu hóa phiên làm việc của Client.
