# Chat History Quá Dài làm Response Chậm và Đắt

## ⚡ Tóm tắt ngắn (30s)
* **Pattern**: long conversation → history accumulates in prompt → each turn cost grows linearly + latency.
* **Strategies**:
  1. **Sliding window**: keep last N turns.
  2. **Summary buffer**: summarize old turns, keep recent raw.
  3. **Entity memory**: extract structured facts, drop raw history.
  4. **Hierarchical summary**: layered.
* **Trade-off**: information loss vs cost.

---

## 💻 Summary buffer pattern

```java
@Service
public class ConversationMemory {
    private static final int RAW_TURN_LIMIT = 10;
    
    public void append(String sessionId, Message turn) {
        var memory = redis.get(sessionId);
        memory.add(turn);
        
        if (memory.rawTurns().size() > RAW_TURN_LIMIT + 5) {
            var toSummarize = memory.rawTurns()
                .subList(0, memory.rawTurns().size() - RAW_TURN_LIMIT);
            
            String summary = summarizer.summarize(toSummarize);
            memory.setSummary(summary);
            memory.replaceRaw(memory.rawTurns()
                .subList(memory.rawTurns().size() - RAW_TURN_LIMIT,
                         memory.rawTurns().size()));
        }
        
        redis.set(sessionId, memory);
    }
    
    public String buildPrompt(Memory m) {
        return "Conversation summary so far: " + m.summary() + "\n\n" +
               "Recent turns:\n" + formatTurns(m.rawTurns());
    }
}
```

## 📊 Strategy comparison

| Strategy | Info loss | Cost saving | Implementation |
| :--- | :---: | :---: | :--- |
| Sliding window | High (drop old) | Best | Simple |
| Summary buffer | Medium | Good | Medium |
| Entity memory | Low (key facts) | Medium | Complex |
| Hierarchical | Low | Best | Complex |
