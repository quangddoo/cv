# So sánh @ConfigurationProperties vs @Value: Chọn công cụ nào để nạp cấu hình?

## ⚡ Tóm tắt ngắn (30s)
Cả hai Annotation đều dùng để nạp cấu hình ngoại vi vào các Spring Beans, nhưng chúng được thiết kế cho các kịch bản sử dụng hoàn toàn khác nhau:
*   **`@Value`**: Thích hợp cho các trường hợp nạp **cấu hình đơn lẻ**, nhanh gọn (ví dụ: nạp một cái API Key, một cái flag enable/disable). Điểm mạnh độc nhất là hỗ trợ cú pháp SpEL (Spring Expression Language) mạnh mẽ, nhưng điểm yếu là không có Type-safety và khó quản lý khi số lượng cấu hình lớn.
*   **`@ConfigurationProperties`**: Được khuyên dùng cho các **nhóm cấu hình có cấu trúc phân cấp, phức tạp** (ví dụ: thông số kết nối Database gồm url, username, password, pool-size). Điểm mạnh vượt trội là hỗ trợ **Type-Safety** (Ràng buộc kiểu dữ liệu rõ ràng), **JSR-303 Bean Validation** (Kiểm tra tính hợp lệ của cấu hình lúc startup), **Relaxed Binding** đầy đủ và khả năng tự động sinh gợi ý code (Autocomplete) trong IDE.

## 🔍 Chi tiết bản chất thực chiến

### 1. Phân biệt 5 điểm cốt lõi giữa hai Annotation

| Tiêu chí | `@Value` | `@ConfigurationProperties` |
| :--- | :--- | :--- |
| **Kiểu nạp cấu hình** | Nạp đơn lẻ từng thuộc tính (Individual Binding). | Nạp cả cụm thuộc tính có chung tiền tố (Bulk/Group Binding). |
| **Type Safety (An toàn kiểu)** | ❌ Không. Nếu map sai kiểu dữ liệu, ứng dụng chỉ crash lúc chạy method (Runtime) chứa Bean đó. |  **Có**. Tự động ép kiểu dữ liệu từ file YAML vào Class POJO. Crash ngay lập tức khi startup nếu sai kiểu. |
| **Hỗ trợ SpEL** |  **Có**. Cho phép tính toán biểu thức động (ví dụ: `#{systemProperties['user.home']}`). | ❌ Không. Chỉ nạp tĩnh trực tiếp các giá trị Key-Value. |
| **Relaxed Binding** | ❌ Hạn chế. Phải khớp chính xác tên key ở một số ngữ cảnh. |  **Đầy đủ**. Tự động chuyển đổi camelCase, kebab-case, snake_case thành tên thuộc tính tương ứng. |
| **Validation (Kiểm thực hợp lệ)**| ❌ Không hỗ trợ trực tiếp. |  **Có**. Tích hợp JSR-303 để validate đầu vào cấu hình (ví dụ: kiểm tra port phải nằm trong khoảng 1024-65535). |
| **Tự động gợi ý trong IDE** | ❌ Không thể. |  **Có**. Khi gõ file `application.yaml` trong IntelliJ/Eclipse, IDE sẽ tự động gợi ý tên thuộc tính. |

## 💻 Code thực chiến: BAD vs GOOD

### ❌ BAD: Lạm dụng hàng tá `@Value` cho một nhóm cấu hình liên đới
Khi cấu hình thông tin cho một Mail Server, lập trình viên viết lặp đi lặp lại nhiều annotation `@Value` cho cùng một tiền tố `mail.*`. Code trở nên cực kỳ cồng kềnh, dễ gõ sai chính tả key và không có bất kỳ cơ chế kiểm soát lỗi cấu hình nào.

```java
package com.example.config;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Configuration;

@Configuration
public class BadMailConfig {

    @Value("${mail.host}") // ⚠️ Phải lặp lại prefix "mail" nhiều lần
    private String host;

    @Value("${mail.port:25}") // ⚠️ Dễ gõ sai giá trị default hoặc gõ sai tên key
    private int port;

    @Value("${mail.username}")
    private String username;

    @Value("${mail.password}")
    private String password;

    @Value("${mail.ssl-enabled:false}")
    private boolean sslEnabled;

    // Getter/Setter rườm rà phía dưới...
}
// ⚠️ Hậu quả: Không thể kiểm tra xem "host" có bị bỏ trống hay không, "port" có bị nhập số âm hay không cho đến khi gửi mail thực tế bị lỗi.
```

###  GOOD: Sử dụng `@ConfigurationProperties` kết hợp Validator lúc Startup
Tạo một lớp POJO sạch sẽ để đại diện cho nhóm cấu hình `mail`. Áp dụng các annotation của gói JSR-303 (như `@NotBlank`, `@Min`, `@Max`) để kiểm soát dữ liệu đầu vào chặt chẽ.

**Bước 1: Khai báo Class Cấu hình chuẩn chỉnh**
```java
package com.example.config;

import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.context.annotation.Configuration;
import org.springframework.validation.annotation.Validated;

@Configuration
@ConfigurationProperties(prefix = "mail") // ✅ Chỉ định tiền tố chung
@Validated // ✅ Bắt buộc kích hoạt kiểm tra tính hợp lệ lúc startup
public class GoodMailProperties {

    @NotBlank(message = "Mail host không được phép bỏ trống!") // Bắt buộc nhập
    private String host;

    @Min(value = 25, message = "Port mail tối thiểu là 25")
    @Max(value = 65535, message = "Port mail tối đa là 65535")
    private int port = 25; // Giá trị mặc định sạch sẽ

    @NotBlank
    private String username;

    @NotBlank
    private String password;

    private boolean sslEnabled = false;

    // Getter và Setter (Spring bắt buộc phải có Setter để tiêm giá trị, trừ khi dùng Constructor Binding)
    public String getHost() { return host; }
    public void setHost(String host) { this.host = host; }
    public int getPort() { return port; }
    public void setPort(int port) { this.port = port; }
    public String getUsername() { return username; }
    public void setUsername(String username) { this.username = username; }
    public String getPassword() { return password; }
    public void setPassword(String password) { this.password = password; }
    public boolean isSslEnabled() { return sslEnabled; }
    public void setSslEnabled(boolean sslEnabled) { this.sslEnabled = sslEnabled; }
}
```

**Bước 2: Sử dụng gọn gàng trong Service nghiệp vụ**
```java
package com.example.service;

import com.example.config.GoodMailProperties;
import org.springframework.stereotype.Service;

@Service
public class MailSenderService {

    private final GoodMailProperties mailProperties;

    // Tiêm cả cụm POJO cấu hình an toàn bằng Constructor
    public MailSenderService(GoodMailProperties mailProperties) {
        this.mailProperties = mailProperties;
    }

    public void sendEmail(String to, String content) {
        // Truy xuất cấu hình cực kỳ an toàn qua Getter và có Type-safety!
        System.out.println("Connecting to mail host: " + mailProperties.getHost() + ":" + mailProperties.getPort());
        System.out.println("Using TLS/SSL: " + mailProperties.isSslEnabled());
    }
}
```

## 📊 Trade-off: Lựa chọn công cụ phù hợp trong thực tế

| Tiêu chuẩn lựa chọn | Nên dùng `@Value` | Nên dùng `@ConfigurationProperties` |
| :--- | :--- | :--- |
| **Quy mô cấu hình** | Nhỏ lẻ (1 đến 2 tham số độc lập). | Lớn, phân cấp, có cấu trúc cây (từ 3 tham số trở lên). |
| **Ràng buộc an toàn** | Không cần khắt khe, chấp nhận rủi ro runtime. | Cần tuyệt đối an toàn dữ liệu, muốn app crash ngay lập tức nếu config sai. |
| **Yêu cầu xử lý động** | Cần xử lý biểu thức phức tạp, tính toán thời gian, lấy thư mục hệ thống. | Chỉ cần nạp các giá trị Key-Value tĩnh từ file cấu hình. |

## ⚠️ Common Gotchas & Questions follow-up

### 1. Quên tạo Setter khi sử dụng `@ConfigurationProperties`
*   **Vấn đề**: Bạn tạo class `@ConfigurationProperties` nhưng quên viết các phương thức Setter (hoặc không dùng Lombok `@Setter`). Kết quả là ứng dụng vẫn khởi động thành công, nhưng toàn bộ các trường dữ liệu đều bị nhận giá trị `null` hoặc mặc định.
*   **Lý do**: Mặc định, Spring Boot sử dụng cơ chế Java Beans truyền thống để nạp cấu hình qua phương thức Setter của đối tượng.
*   **Khắc phục**: Luôn tạo đầy đủ Getter/Setter, hoặc sử dụng tính năng **Constructor Binding** của Spring Boot bằng cách đổi class thành một Java **`record`** (Từ Spring Boot 3.0+ trở lên, các record tự động được kích hoạt Constructor Binding nếu được đánh dấu `@ConfigurationProperties`).

### 2. Làm sao để kích hoạt tính năng tự động gợi ý code (Autocomplete) trong file `.yaml` của IDE?
Interviewer thường hỏi: *"Làm sao để khi tôi gõ cấu hình custom trong application.yaml, Intellij IDEA tự động gợi ý các trường có trong class @ConfigurationProperties của tôi?"*
*   **Trả lời**: Hãy khai báo thư viện xử lý metadata của Spring Boot vào phần dependencies của file `pom.xml` / `build.gradle`:
    ```xml
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-configuration-processor</artifactId>
        <optional>true</optional>
    </dependency>
    ```
    Khi bạn biên dịch dự án (compile), thư viện này sẽ tự động phân tích các class có chứa `@ConfigurationProperties` và sinh ra một file JSON chứa siêu dữ liệu tại đường dẫn `target/classes/META-INF/spring-configuration-metadata.json`. IDE sẽ đọc file này để hỗ trợ gợi ý autocomplete cực kỳ mượt mà cho lập trình viên.
