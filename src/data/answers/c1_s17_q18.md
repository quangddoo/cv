# Tìm tổng hai số và tổng ba số (Two Sum and Three Sum)

## ⚡ Tóm tắt ngắn (30s)
* **Bài toán**: 
  * **Two Sum (Tổng hai số)**: Tìm cặp chỉ mục (indices) của hai số trong mảng sao cho tổng của chúng bằng một số `target` cho trước.
  * **Three Sum (Tổng ba số)**: Tìm tất cả các bộ ba số duy nhất (triplets) trong mảng có tổng bằng `0`.
* **Giải pháp cốt lõi**:
  * **Two Sum**: Sử dụng một bảng băm **`HashMap`** lưu trữ giá trị và chỉ mục của các số đã duyệt. Duyệt qua mảng, với mỗi số `nums[i]`, kiểm tra xem hiệu `target - nums[i]` đã tồn tại trong Map chưa. Nếu có, trả về kết quả ngay lập tức.
  * **Three Sum**:
    1. **Sắp xếp mảng** tăng dần: Tạo điều kiện áp dụng kỹ thuật hai con trỏ và loại bỏ trùng lặp dễ dàng.
    2. **Duyệt một vòng lặp kết hợp hai con trỏ (Two Pointers)**: Cố định vị trí số thứ nhất `i`. Thiết lập hai con trỏ `left = i + 1` và `right = N - 1` chạy co cụm từ hai đầu để tìm hai số còn lại.
    3. **Loại bỏ trùng lặp (Deduplication)**: Cực kỳ quan trọng, bỏ qua các phần tử trùng nhau liên tiếp ở cả 3 con trỏ để đảm bảo bộ ba thu được là duy nhất.
* **Độ phức tạp**:
  * **Two Sum**: Thời gian $O(N)$, không gian $O(N)$ nhờ bảng băm.
  * **Three Sum**: Thời gian $O(N^2)$, không gian $O(\log N)$ hoặc $O(1)$ phụ thuộc giải thuật sắp xếp.

## 🔍 Phân tích yêu cầu (Requirements)

### 1. Functional Requirements (Yêu cầu chức năng)
* **Two Sum**: Mỗi dữ liệu đầu vào có đúng một giải pháp duy nhất. Không được phép sử dụng cùng một phần tử hai lần.
* **Three Sum**: Kết quả trả về phải chứa các bộ ba số **duy nhất**, không chứa các bộ trùng lặp (ví dụ: `[1, -1, 0]` và `[-1, 1, 0]` được coi là trùng lặp).

### 2. Non-Functional Requirements (Yêu cầu phi chức năng)
* **Hiệu năng cao**: Thuật toán Three Sum phải vượt qua được các test case cực lớn của Leetcode mà không bị lỗi quá thời gian chạy (Time Limit Exceeded - TLE) bằng cách loại bỏ sớm các nhánh vô nghiệm (Pruning).

## 🎨 Sơ đồ trực quan & Giải thuật

### Kỹ thuật hai con trỏ (Two Pointers) trong giải bài toán Three Sum

Giả sử sau khi sắp xếp mảng ta có: `nums = [-4, -1, -1, 0, 1, 2]`

```
 Vòng lặp i = 0: nums[i] = -4 (Cố định)
   left = i + 1 (Trỏ vào -1)                                  right = N - 1 (Trỏ vào 2)
     ▼                                                            ▼
   [-4,   -1,   -1,   0,   1,   2]  ===> Tổng = -4 + (-1) + 2 = -3 < 0
                                         ===> Tổng âm, cần tăng: left++

 Vòng lặp i = 1: nums[i] = -1 (Cố định)
   left = i + 1 (Trỏ vào -1)                                  right = N - 1 (Trỏ vào 2)
     ▼                                                            ▼
   [-4,   -1,   -1,   0,   1,   2]  ===> Tổng = -1 + (-1) + 2 = 0 (KHỚP!)
                                         ===> Thu được bộ: [-1, -1, 2]
                                         ===> left++, right-- và bỏ qua các số trùng lặp

             left (Trỏ vào 0)                       right (Trỏ vào 1)
                 ▼                                      ▼
   [-4,   -1,   -1,   0,   1,   2]  ===> Tổng = -1 + 0 + 1 = 0 (KHỚP!)
                                         ===> Thu được bộ: [-1, 0, 1]
```

## 💻 Code Example: Hiện thực hóa cấu trúc bằng Java

Dưới đây là mã nguồn Java hoàn chỉnh tích hợp cả hai thuật toán tối ưu bậc nhất cho Two Sum và Three Sum, kèm theo cơ chế loại bỏ trùng lặp và cắt nhánh tối ưu:

```java
import java.util.*;

public class SumOperations {

    /**
     * Thuật toán Two Sum sử dụng HashMap tối ưu thời gian O(N)
     */
    public int[] twoSum(int[] nums, int target) {
        if (nums == null || nums.length < 2) {
            return new int[0];
        }

        // Map lưu giữ: Key là Giá trị phần tử, Value là Chỉ mục của phần tử đó
        Map<Integer, Integer> map = new HashMap<>();

        for (int i = 0; i < nums.length; i++) {
            int complement = target - nums[i];

            // Nếu phần bù đã tồn tại trong Map, trả về kết quả lập tức
            if (map.containsKey(complement)) {
                return new int[] { map.get(complement), i };
            }

            // Lưu phần tử hiện tại vào Map
            map.put(nums[i], i);
        }

        return new int[0]; // Trả về mảng rỗng nếu không tìm thấy
    }

    /**
     * Thuật toán Three Sum sử dụng Sắp xếp + Two Pointers tối ưu thời gian O(N^2)
     */
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        if (nums == null || nums.length < 3) {
            return result;
        }

        // Bước 1: Sắp xếp mảng tăng dần để áp dụng Two Pointers
        Arrays.sort(nums);
        int n = nums.length;

        for (int i = 0; i < n - 2; i++) {
            // Nhánh cắt tối ưu (Pruning): Vì mảng đã sắp xếp, 
            // nếu số đầu tiên nums[i] > 0 thì tổng ba số chắc chắn > 0 (Gotcha 2)
            if (nums[i] > 0) {
                break;
            }

            // Loại bỏ trùng lặp cho con trỏ i (Số thứ nhất)
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }

            int left = i + 1;
            int right = n - 1;

            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];

                if (sum == 0) {
                    result.add(Arrays.asList(nums[i], nums[left], nums[right]));

                    // Loại bỏ trùng lặp cho con trỏ left (Số thứ hai)
                    while (left < right && nums[left] == nums[left + 1]) {
                        left++;
                    }
                    // Loại bỏ trùng lặp cho con trỏ right (Số thứ ba)
                    while (left < right && nums[right] == nums[right - 1]) {
                        right--;
                    }

                    // Đồng thời di chuyển cả 2 con trỏ vào sâu hơn
                    left++;
                    right--;
                } else if (sum < 0) {
                    // Tổng quá nhỏ, cần tăng số ở con trỏ left để tăng tổng
                    left++;
                } else {
                    // Tổng quá lớn, cần giảm số ở con trỏ right để giảm tổng
                    right--;
                }
            }
        }

        return result;
    }

    // --- Hàm Demo chạy thử ---
    public static void main(String[] args) {
        SumOperations solver = new SumOperations();

        // Test Two Sum
        int[] nums2 = {2, 7, 11, 15};
        int[] ans2 = solver.twoSum(nums2, 9);
        System.out.println("Two Sum Result (target = 9): " + Arrays.toString(ans2)); // [0, 1]

        // Test Three Sum
        int[] nums3 = {-1, 0, 1, 2, -1, -4};
        List<List<Integer>> ans3 = solver.threeSum(nums3);
        System.out.println("\nThree Sum Result (sum = 0): " + ans3); 
        // [[-1, -1, 2], [-1, 0, 1]]
    }
}
```

## 📊 Phân tích độ phức tạp & Trade-offs

### Phân tích chiến lược giải quyết Three Sum

| Giải pháp | Brute Force (3 vòng lặp lồng nhau) | Sử dụng HashMap trung gian | Sử dụng Sắp xếp + Two Pointers (Tối ưu) |
| :--- | :--- | :--- | :--- |
| **Mô tả** | Duyệt qua mọi bộ ba số bằng 3 vòng `for` lồng nhau. | Giữ cố định `i` và `j`, dùng HashMap tìm phần bù `-(nums[i] + nums[j])`. | Sắp xếp mảng trước, cố định `i`, co cụm hai con trỏ `left` và `right` để tìm phần bù. |
| **Độ phức tạp thời gian** | **Cực kém**: $O(N^3)$. | **Tốt**: $O(N^2)$ nhưng chạy thực tế chậm hơn do chi phí Hash. | **Tuyệt vời**: $O(N^2)$ do chi phí sắp xếp $O(N \log N)$ bị lấn át hoàn toàn bởi $O(N^2)$. |
| **Độ phức tạp bộ nhớ** | **Tối ưu**: $O(1)$ không dùng thêm bộ nhớ. | **Kém**: $O(N)$ để lưu trữ dữ liệu trong Map kiểm tra trùng. | **Tốt**: $O(1)$ bộ nhớ bổ sung (hoặc $O(\log N)$ bộ nhớ lưu ngăn xếp đệ quy của thuật toán sắp xếp). |
| **Xử lý trùng lặp (Deduplication)** | Phức tạp, phải đưa kết quả vào Set để lọc lại. | Khó khăn khi loại bỏ các bộ trùng lặp có thứ tự phần tử khác nhau. | **Dễ dàng và tự nhiên** nhờ mảng đã được sắp xếp sẵn. |

## ⚠️ Common Gotchas (Câu hỏi đào sâu từ interviewer)

### 1. Tại sao trong Three Sum ta không nên sử dụng giải pháp HashMap để tìm phần tử thứ 3 (tương tự Two Sum) mặc dù độ phức tạp lý thuyết vẫn là $O(N^2)$?
* **Trả lời**: Đây là câu hỏi rất sâu về thiết kế giải thuật:
  * **Trùng lặp kết quả (Deduplication)**: Điểm khó nhất của Three Sum là loại bỏ các bộ ba trùng lặp (ví dụ `[1, 2, -3]` và `[-3, 1, 2]`). Nếu dùng HashMap, do các phần tử phân bố ngẫu nhiên không có thứ tự, ta sẽ cực kỳ chật vật để nhận diện xem bộ ba vừa tìm được đã từng được lưu hay chưa. Thường phải dùng một `HashSet<List<Integer>>` bổ sung để lọc lại dẫn đến phình to tài nguyên và thời gian chạy.
  * **Hiệu năng thực tế**: Thao tác băm trên Map (Hash Overhead) và cấp phát đối tượng động trên Heap tiêu tốn nhiều tài nguyên hơn rất nhiều so với việc trượt con trỏ nguyên thủy trên mảng tĩnh đã sắp xếp. Kỹ thuật Two Pointers tận dụng tốt cơ chế lưu đệm cache của CPU (CPU Cache Locality) giúp tăng tốc độ thực tế gấp nhiều lần.

### 2. Ý nghĩa của kỹ thuật "Pruning" (Cắt nhánh sớm) trong code Three Sum trên là gì?
* **Trả lời**:
  * Dòng lệnh `if (nums[i] > 0) { break; }` chính là kỹ thuật cắt nhánh tối ưu cực kỳ đắt giá.
  * **Giải thích**: Do mảng đã sắp xếp tăng dần, nếu tại vị trí số thứ nhất `nums[i]` lớn hơn 0, thì chắc chắn tất cả các số tiếp theo nằm bên phải nó (`nums[left]` và `nums[right]`) cũng sẽ lớn hơn 0. Tổng của ba số lớn hơn 0 thì không bao giờ có thể bằng 0 được nữa. Do đó, ta lập tức dừng vòng lặp `break`, bỏ qua toàn bộ các tính toán vô nghĩa còn lại phía sau, tăng tốc độ xử lý lên vượt trội.

### 3. Đối với bài toán Two Sum, nếu mảng đầu vào ĐÃ ĐƯỢC SẮP XẾP SẴN, bạn có thể tối ưu không gian bộ nhớ (Space Complexity) xuống $O(1)$ mà vẫn đảm bảo thời gian $O(N)$ không?
* **Trả lời**:
  * **Có!** Nếu mảng đầu vào đã được sắp xếp sẵn, ta không cần dùng đến `HashMap` ($O(N)$ RAM) nữa.
  * **Giải pháp**: Áp dụng kỹ thuật hai con trỏ (Two Pointers) chạy co cụm từ hai đầu mảng:
    * Đặt `left = 0` và `right = N - 1`.
    * Đoán tổng `sum = nums[left] + nums[right]`.
    * Nếu `sum == target`: trả về cặp chỉ mục.
    * Nếu `sum < target`: dịch con trỏ `left++` để tăng tổng.
    * Nếu `sum > target`: dịch con trỏ `right--` để giảm tổng.
  * **Độ phức tạp**: Thời gian $O(N)$, bộ nhớ bổ sung đạt mức tối ưu tuyệt đối $O(1)$!
