# Edge cases và test case — Test từ contract, không test ngẫu nhiên
## Câu trả lời mẫu
Tôi lập nhóm test theo contract: input rỗng hoặc nhỏ nhất, một phần tử, duplicate, giá trị âm hoặc biên số nguyên, dữ liệu đã sort/ngược, nhiều đáp án, không có đáp án và input lớn. Với graph hoặc tree, tôi thêm node cô lập, cycle, depth lớn và disconnected component khi phù hợp.

Mỗi test cần kiểm tra expected behavior chứ không chỉ chạy cho có. Tôi thường trace một case bằng tay trước, rồi dùng brute-force oracle cho input nhỏ nếu cần so sánh với solution tối ưu. Tôi cũng nói về constraint violation: reject, return empty hay throw exception phải theo contract, không tự đoán.

**Tín hiệu cần thể hiện:** cẩn thận, hiểu boundary của bài toán và có thói quen validate trước khi tuyên bố hoàn tất.
