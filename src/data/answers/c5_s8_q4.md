# Khi nào Dùng Open-source / Self-hosted Model

## ⚡ Tóm tắt ngắn (30s)
Refer c5_s1_q14.

* **Self-host khi**:
  1. **Compliance / data residency**: PHI, financial data can't leave premise.
  2. **Volume > 100M token/day**: TCO self-host < API at very large scale.
  3. **Latency ultra-low** (<100ms): GPU on-prem near app.
  4. **Need full fine-tune**: open-weights only.
  5. **Strategic provider risk**: avoid single point of failure.
* **API khi**: 80% case. Time-to-market, quality, ops simplicity.

---

## 📊 Decision factors

| Factor | Self-host | API |
| :--- | :---: | :---: |
| <10M token/day | ✗ overkill | ✓ |
| 100M+ token/day narrow task | ✓ cheaper | ✗ |
| Compliance strict | ✓ | depends on DPA |
| MLOps team available | ✓ | not needed |
| Want latest model | ✗ behind | ✓ frontier |
| Fine-tune full | ✓ | only LoRA via API |

## ⚠️ Interviewer

**"Cost migrate 50M token/day OpenAI → self-host?"**
TCO 1-year:
- API: $30k/month × 12 = $360k.
- Self-host (4 GPUs reserved): $15k/month infra + $5k MLOps + $3k ops = $23k/month × 12 = $276k.
- Migration: $50k.

Saving ~$30k/year. Plus operational complexity. Recommend: hybrid managed (Bedrock with same model) before pure self-host.
