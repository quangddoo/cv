# Provider A Down, Chuyển sang B nhưng Quality khác

## ⚡ Tóm tắt ngắn (30s)
* **Situation**: failover working but secondary model gives different quality (e.g. Anthropic Sonnet → Bedrock Llama-3-70b → quality drop 15%).
* **Strategies**:
  1. **Communicate to users**: "Running in fallback mode, response may be slower/different".
  2. **Adapt prompt**: each provider may need different prompt formatting.
  3. **Quality-acceptance threshold**: if drop > X%, prefer error over bad response.
  4. **Async retry**: queue requests for primary when restored.
  5. **Cost adjustment**: alert finance team.

---

## 🔍 Handling

### 1. User communication
```html
<banner type="warning">
AI is currently running in backup mode. Responses may differ slightly. We're working to restore.
</banner>
```

### 2. Prompt adaptation
```java
public String adaptPromptForProvider(String basePrompt, String provider) {
    return switch (provider) {
        case "openai" -> basePrompt;  // baseline
        case "anthropic" -> basePrompt;  // similar
        case "bedrock-llama" -> basePrompt + "\n\nIMPORTANT: keep response under 200 words, factual.";
        default -> basePrompt;
    };
}
```

### 3. Quality gate
```java
public LlmResponse failoverWithQuality(LlmRequest req) {
    try {
        return primary.chat(req).get();
    } catch (Exception e) {
        var fallback = secondary.chat(req).get();
        if (!qualityChecker.acceptable(fallback)) {
            // Better to fail than serve garbage
            throw new ServiceDegradedException("Quality fallback unacceptable");
        }
        return fallback.withMetadata("fallback", true);
    }
}
```

### 4. Async retry on primary
```java
// When primary recovers, replay queued requests
@KafkaListener(topics = "primary.recovered")
public void onRecovery() {
    queuedRequests.poll(50)
        .forEach(req -> primary.chat(req).subscribe(
            resp -> userNotifier.sendUpdate(req.userId(),
                "Updated response: " + resp.text())));
}
```

## ⚠️ Interviewer

**"Anthropic Sonnet down 2h. Failover to Llama via Bedrock. Quality drop 20%. Action?"**
1. **Immediate**: communicate to users.
2. **Adapt**: prompt tweaks for Llama.
3. **Filter**: route only simple tasks to Llama; complex → error gracefully.
4. **Queue**: complex tasks queued for primary recovery.
5. **Postmortem**: invest in better fallback (warm cluster, additional providers).
6. **Customer impact**: refund / credit for affected enterprise.
