# Deep Dive Approach — Ôn theo Chuỗi Câu hỏi

## ⚡ Tóm tắt ngắn (30s)
* **Deep dive** = không chỉ học định nghĩa, mà tự trả lời chuỗi 5-10 câu hỏi đào sâu cho mỗi topic.
* **Format**: cho mỗi concept → ask "Why?", "How?", "What if X?", "Trade-off?", "Production gotcha?".
* **Topics phải deep dive**:
  - Kafka (partitioning, consumer group, exactly-once).
  - Spring Transaction (propagation, isolation).
  - JPA (N+1, lazy/eager, dirty checking).
  - Redis (eviction, persistence, cluster).
  - Database index (B-tree, partial, composite).
  - Thread pool (size, queue, rejection).
  - Retry + timeout + circuit breaker.

---

## 🔍 Phương pháp

### Pattern: 5-Why chain

Ví dụ topic Kafka partitioning:
1. **What** is partition?
2. **Why** partition? (scale, parallel consume).
3. **How** message route to partition? (key hash).
4. **What if** consumer fail? (offset commit, rebalance).
5. **Production gotcha**: hot partition, rebalance storm.
6. **Trade-off**: more partitions = more parallelism but more file handles.

### Template per topic

```
## {Topic}

### Definition
What is it?

### Why exists
Problem it solves.

### How works
Internal mechanism step-by-step.

### Configuration knobs
What to tune.

### Production pitfalls
3-5 common issues.

### Trade-offs
Alternative approaches.

### Real example you handled
Story from your experience.

### Follow-up questions
What interviewer might ask next.
```

## 💻 Example: Spring Transaction Deep Dive

### Q1: @Transactional là gì?
AOP proxy wraps method, opens DB transaction before, commits/rollbacks after.

### Q2: Propagation levels?
REQUIRED (default), REQUIRES_NEW, NESTED, SUPPORTS, NOT_SUPPORTED, NEVER, MANDATORY.

### Q3: Default propagation behavior?
REQUIRED: join existing tx if any, else new.

### Q4: REQUIRES_NEW use case?
Audit log: want commit even if outer rolled back.

### Q5: Why self-invocation bypass?
Proxy only intercepts public method call from OUTSIDE the bean. Self-call goes through `this`, skips AOP.

### Q6: How fix self-invocation?
Inject self proxy via @Autowired, or move logic to separate bean.

### Q7: Isolation levels in @Transactional?
READ_UNCOMMITTED → READ_COMMITTED → REPEATABLE_READ → SERIALIZABLE.

### Q8: Default isolation?
DB default (Postgres = READ_COMMITTED, MySQL = REPEATABLE_READ).

### Q9: Rollback rules?
By default: RuntimeException rollback, checked Exception NO rollback. Override với `rollbackFor = Exception.class`.

### Q10: Production gotcha?
- LazyInitializationException: lazy load outside tx.
- Long transaction holding locks → deadlock.
- Optimistic vs pessimistic locking choice.

## ⚠️ Common Mistakes & Pro Tips

1. **Memorize answers**: bad. Internalize concept.
2. **Skip "Why"**: only memorize "What".
3. **No real-world**: no production story = junior signal.
4. **One-level deep**: stop at definition; go 5 layers.
5. **No comparison**: compare with alternative (e.g. Kafka vs RabbitMQ).
