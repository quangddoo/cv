# Spring Transaction Propagation: 7 Loại lan truyền Giao dịch thực chiến

## ⚡ Tóm tắt ngắn (30s)
`Transaction Propagation (Lan truyền giao dịch)` quy định cách một phương thức `@Transactional` hành xử khi được gọi bởi một phương thức khác đã có sẵn giao dịch (Active Transaction) hoặc chưa.
Spring Boot hỗ trợ đầy đủ 7 loại lan truyền, trong đó có **3 loại cốt lõi** thường xuyên xuất hiện trong các dự án thực tế và các buổi phỏng vấn:
1.  **`REQUIRED` (Mặc định)**: Gia nhập vào giao dịch hiện tại nếu có. Nếu chưa có giao dịch nào đang chạy, nó sẽ mở một giao dịch mới.
2.  **`REQUIRES_NEW`**: Luôn tạm dừng (suspend) giao dịch hiện tại và mở một giao dịch mới độc lập hoàn toàn. Lỗi của giao dịch mới này commit hay rollback không ảnh hưởng gì tới giao dịch cha (nếu được bắt lỗi đúng cách).
3.  **`NESTED`**: Chạy lồng bên trong giao dịch hiện tại thông qua cơ chế **Savepoint (Điểm lưu trữ)** của Database. Giao dịch con có thể rollback độc lập về điểm savepoint mà không làm rollback giao dịch cha. Nhưng nếu giao dịch cha bị rollback, toàn bộ giao dịch con cũng bị rollback theo.

## 🔍 Chi tiết bản chất thực chiến

### 1. Bảng giải nghĩa chi tiết 7 loại Propagation trong Spring

| Loại Propagation | Hành vi khi đã có Transaction cha | Hành vi khi CHƯA có Transaction cha | Ứng dụng thực tế |
| :--- | :--- | :--- | :--- |
| **`REQUIRED`** (Default) | Chạy chung với cha (Dùng chung connection). | Mở Transaction mới. | Dùng cho 95% tác vụ CRUD nghiệp vụ thông thường. |
| **`REQUIRES_NEW`** | Tạm dừng cha, mở Transaction con mới độc lập. | Mở Transaction mới. | 📌 Rất quan trọng: Ghi log hệ thống, Audit Log, trừ tiền ví phụ độc lập. |
| **`NESTED`** | Tạo một **Savepoint** lồng trong Transaction cha. | Mở Transaction mới. | Thực hiện thanh toán từng phần, nếu một bước lỗi thì thử lại bước khác. |
| **`MANDATORY`** | Chạy chung với cha. | ❌ **Ném Exception** (`IllegalTransactionStateException`). | Các tác vụ hạ tầng nhạy cảm bắt buộc phải chạy dưới sự bảo hộ của cha. |
| **`SUPPORTS`** | Chạy chung với cha. | Chạy dạng KHÔNG có Transaction. | Dùng cho các phương thức đọc (Read-only) dữ liệu. |
| **`NOT_SUPPORTED`** | Tạm dừng cha, chạy dạng KHÔNG Transaction. | Chạy dạng KHÔNG có Transaction. | Dùng khi cần đọc dữ liệu dung lượng lớn để tránh block DB Connection. |
| **`NEVER`** | ❌ **Ném Exception**. | Chạy dạng KHÔNG có Transaction. | Chặn đứng việc vô tình chạy transaction ở những luồng cấm. |

### 2. Sự khác biệt bản chất giữa REQUIRES_NEW và NESTED

```text
REQUIRES_NEW (Hai kết nối vật lý độc lập):
[Transaction Cha (Connection 1)] ──(Tạm dừng)──> [Transaction Con (Connection 2)] 
* Lỗi của Con rollback -> Cha có thể catch và tiếp tục commit Connection 1 thành công.
* Lỗi của Cha rollback -> Con ĐÃ commit từ trước thành công, không bị ảnh hưởng.

NESTED (Một kết nối vật lý duy nhất sử dụng Savepoint):
[Transaction Cha (Connection 1)] ──(Tạo Savepoint A)──> [Transaction Con (Connection 1)]
* Lỗi của Con rollback -> Chỉ rollback về Savepoint A. Cha có thể tiếp tục xử lý và commit.
* Lỗi của Cha rollback -> TOÀN BỘ Transaction (bao gồm cả Con) bị rollback sạch bóng!
```

## 💻 Code thực chiến: BAD vs GOOD

### ❌ BAD: Dùng REQUIRED mặc định khiến Audit Log bị bay màu khi nghiệp vụ chính lỗi
Bạn muốn ghi nhận lại hành động của khách hàng vào bảng `audit_logs` trước khi trừ tiền mua hàng. Nếu trừ tiền thất bại (lỗi số dư), bạn vẫn muốn giữ lại dòng log để biết khách hàng đã cố gắng mua hàng. Nhưng do dùng mặc định (REQUIRED), khi mua hàng lỗi, toàn bộ transaction bị rollback và **Log cũng bị xóa sạch**!

```java
package com.example.service;

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class OrderServiceBad {

    private final AuditLogServiceBad auditLogService;

    public OrderServiceBad(AuditLogServiceBad auditLogService) {
        this.auditLogService = auditLogService;
    }

    @Transactional
    public void purchase(Long userId, double amount) {
        // SQL 1: Ghi log
        auditLogService.writeLog(userId, "User tried to purchase item");

        // SQL 2: Trừ tiền (Giả sử xảy ra lỗi thiếu tiền)
        System.out.println("SQL: Update user_balance set amount = amount - " + amount);
        if (amount > 100) {
            throw new RuntimeException("Insufficient balance!"); // ⚠️ Ném lỗi!
        }
        // Hậu quả: Do dùng chung Transaction (REQUIRED), khi ném lỗi, 
        // cả dòng Audit Log cũng bị ROLLBACK mất tích, hệ thống không lưu vết được sự kiện!
    }
}

@Service
public class AuditLogServiceBad {
    @Transactional // Mặc định là REQUIRED
    public void writeLog(Long userId, String action) {
        System.out.println("SQL: Insert into audit_logs values (" + userId + ", '" + action + "')");
    }
}
```

###  GOOD: Sử dụng `REQUIRES_NEW` để bảo vệ Audit Log độc lập
Tách biệt lan truyền giao dịch của `AuditLogService` thành `REQUIRES_NEW`. Điều này bắt buộc Spring mở một Transaction và Connection mới hoàn toàn để commit log ngay lập tức, bất chấp giao dịch mua hàng của cha thành công hay thất bại.

```java
package com.example.service;

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class AuditLogServiceGood {

    // ✅ Ép buộc mở một Connection mới độc lập để ghi log ngay lập tức!
    @Transactional(propagation = Propagation.REQUIRES_NEW) 
    public void writeLog(Long userId, String action) {
        System.out.println("SQL: Insert into audit_logs safely via NEW connection...");
    }
}

@Service
public class OrderServiceGood {

    private final AuditLogServiceGood auditLogService;

    public OrderServiceGood(AuditLogServiceGood auditLogService) {
        this.auditLogService = auditLogService;
    }

    @Transactional(rollbackFor = Exception.class)
    public void purchase(Long userId, double amount) {
        // Ghi log độc lập trước
        try {
            auditLogService.writeLog(userId, "Purchase attempt for amount: " + amount);
        } catch (Exception e) {
            System.out.println("Log failed, but do not stop the purchase business!");
        }

        // Thực hiện nghiệp vụ chính
        System.out.println("SQL: Update user_balance...");
        if (amount > 100) {
            // ✅ OK: Khi ném lỗi ở đây, DB rollback việc trừ tiền,
            // nhưng Audit Log đã được commit thành công ở Connection độc lập kia!
            throw new RuntimeException("Insufficient balance!"); 
        }
    }
}
```

## ⚠️ Common Gotchas & Questions follow-up

### Cạm bẫy kinh điển: Lỗi `UnexpectedRollbackException`
Đây là lỗi cực kỳ hay gặp khiến nhiều lập trình viên mất hàng giờ debug:
*   **Kịch bản**: Method cha A gọi method con B (cả hai đều mặc định `@Transactional` - REQUIRED). Method con B bị lỗi ném `RuntimeException`. Method cha A viết khối `try-catch` bọc quanh lời gọi B để nuốt exception nhằm mục đích tiếp tục thực hiện các câu lệnh SQL khác của cha và mong muốn commit thành công.
*   **Hậu quả**: Khi kết thúc method cha A, Spring cố gắng commit nhưng bất ngờ quăng lỗi **`UnexpectedRollbackException`** và rollback sạch toàn bộ giao dịch!
*   **Nguyên nhân dưới mui xe**: Do dùng `REQUIRED`, cả A và B dùng chung 1 transaction vật lý duy nhất. Khi B bị lỗi, Spring interceptor đánh dấu (mark) giao dịch này là **"Rollback-Only"**. Cho dù cha A có catch lỗi và nuốt đi, trạng thái "Rollback-Only" của transaction đã bị đóng đinh. Khi cha kết thúc và gửi lệnh commit, Spring phát hiện trạng thái này và lập tức từ chối, quăng lỗi cảnh báo bảo mật dữ liệu.
*   **Giải pháp xử lý**:
    1.  Nếu muốn lỗi của con không ảnh hưởng tới cha: **Bắt buộc phải khai báo con là `REQUIRES_NEW`** để cô lập transaction vật lý của con ra ngoài cha.
    2.  Hoặc sử dụng `NESTED` (Nếu database và JPA provider của bạn hỗ trợ savepoints).
