# Trade-off Cache vs Correctness trong AI Response

## ⚡ Tóm tắt ngắn (30s)
* **Cache win**: 50-90% cost saving, 10-100x latency improvement.
* **Cache lose**: stale data, wrong cross-user, miss personalization.
* **Solution**:
  1. **Cache key includes context** (user_id for personalized, doc_version for RAG).
  2. **TTL**: shorter for volatile, longer for stable.
  3. **Invalidate on change**: event-driven.
  4. **Don't cache** personalized, realtime, low temperature changing.

---

## 📊 What to cache

| Type | Cache? | TTL |
| :--- | :---: | :---: |
| FAQ answer (static) | ✓ | 24h |
| Product description | ✓ | 1h (sync source) |
| User profile QA | ✗ | - |
| Realtime data | ✗ | - |
| Code snippets (gen) | ✓ if temp=0 | 1h |

## 💻 Smart cache

```java
public class SmartLlmCache {
    public Optional<String> get(LlmRequest req) {
        if (!isCacheable(req)) return Optional.empty();
        String key = computeKey(req);
        return Optional.ofNullable(redis.get(key));
    }
    
    private boolean isCacheable(LlmRequest req) {
        return req.temperature() == 0.0
            && req.userId() == null  // not personalized
            && !req.purpose().startsWith("realtime");
    }
    
    private String computeKey(LlmRequest req) {
        return sha256(req.systemPrompt() + req.userPrompt() + req.model());
    }
}
```

## ⚠️ Interviewer

**"Aggressive caching saved $50k. Correctness?"**
1. Monitor: # cache hits that were "wrong" (user reports).
2. Validate by sampling: 1% cache hits → re-generate, compare.
3. If divergence > X%, tighten cache or shorter TTL.
4. Balance: cost saving worth small correctness risk in some use cases.
